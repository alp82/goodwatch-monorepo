# Continuous choosing — contract 2

2026-10-22. Import `@goodwatch/yepwatch-contracts/continuous`. Portable, dependency-free DTOs only. Legacy `index.ts`, phase meanings, rooms, table and retained processes stay untouched. New routes are **/api/yepwatch/v1/continuous/**; use a new app/API/gateway deployment together, never parse a contract1 room as contract2. Separate implementation table: `doc.yepwatch_room_v2`; no automatic migration.

- Entry -> setup -> choosing -> decided; no complete_round, shortlist, host proposal/consent/finalize.
- Nope=`pass`, Yep=`watch`, undo=null with own vote revision. Matches are immediately all-current-required-participant Watch, including newly admitted people with zero invented responses. Match arrival never navigates or interrupts choosing.
- Pick is one own private candidateId+revision, nullable. Selecting another replaces it; viewing another screen/card never clears it. Shared match contains anonymous pickCount only. Any roster/undo change removing a match clears every pick on it. Disconnect/away changes no durable state/quorum.
- Pick command fences generation, rosterVersion and own pick revision. Unanimous current picks schedule an automatic durable checking state; API rechecks all viewing screens, then CAS commits or records unavailable. Retry agreement is repair, not host permission. No decision before durable fresh evidence. New join/undo/pick during a held check must defeat it.
- Candidate stream appends through refill command expectedStreamVersion+generation, dedupes canonical title identities, retains unresolved/matched candidates and bounded seen identities. No automatic next-round reset at end. Honest exhausted/incomplete/capacity state; no infinite guarantee. Own nextCandidateId is private; exact UI focus while inspecting matches belongs to client state and is never an activity payload.
- Candidate optional backdropUrl/trailerUrl/goodwatchScore/genres come only from catalog. Provider evidence scope stays title/episode and never proves individual subscription entitlement.
- Browser admission: HttpOnly room cookie, returned token empty. Native: scoped bearer plus participant header. Same-cookie admission recovers existing identity. Sequence/id/body retry unchanged. New contract2 admission explicitly sends contractVersion:2.
- Attach/view/ticket use the exported continuous paths and the existing authenticated one-use ticket / rotating scoped lease semantics. Separate v2 revision hints (roomId,revision only) and v2 ephemeral activity channel isolate old demos.
- Activity ack follows authorized snapshot. Per-session monotonic sequence, view voting|matches|trailer|away, optional reach|handle|release or answer beat. No coordinates/card/title/index/direction/value/pick target. Server assigns actor/room/session/time; viewTTL6000ms, pulseTTL1500ms, foreground view renewal<=3000ms,4fps/burst8 + participant aggregate cap. Close affects only that activity session; no membership mutation.
- Optional member integration uses the existing central GoodWatch issuer with dedicated public PKCE client/resource/read scope and live-grant checks. Status/start/exchange and private saved-progress shapes are implemented; production client/config rollout and physical-device return are unverified. No manual progress endpoint. Saved-progress continuation cannot be enabled by client assertions.

Current limits are documented in the backend runbook. Leave/kick/host-transfer UI is excluded; security revocation retains required quorum. Current post-decision policy: admission refuses closed room until explicit host restart; never silently revokes a committed decision. Required participants are never dropped due to disconnect.

Member callback agreement: `MemberStartResponse.state` is the explicit expected OAuth state; native persists it with verifier+roomId before opening the browser. Native return is configured exactly `yepwatch://auth/callback?roomId=...&state=...&code=...`; exchange requires those three values plus original verifier and existing room credential. The registered issuer redirect is always the namespaced API callback, never the private return URI. Browser returnTo is exactly its approved app origin plus `/room/<roomId>`, with no query/hash. Browser callback requires the original participant cookie; native uses PKCE and authenticated exchange. Account linkage never replaces an existing linked subject. Codes/state must be redacted from logs.

The API callback ends issuer consent navigation with a protected no-store HTML document, then auto-navigates to the checked app URI (plus explicit return link); it does not chain another HTTP redirect. This avoids issuer form-action rejection of a separate web origin/native scheme. Short-lived member grants currently require sign-in again on expiry; refresh rotation is a tracked implementation gap. Private saved progress uses established GoodWatch tracking keys/next-episode semantics, and continuation requires an exact common next episode across every signed-in required participant. Guests never submit history.
