# V2 architecture and page impact

**GoodWatch can support the proposed format through a versioned migration; the compact LLM JSON cannot replace V1 directly.** This document records static repository findings on October 19, 2026 and proposed adaptations. No generation, database, deployment, external service or page runtime was exercised. The [definition](../definition.json), [compact vocabulary](../llm-definition.json) and [gap recommendations](../../../research/fingerprint-v2-gap-audit/recommended-changes.json) remain proposals.

## Source of truth, generation and companion outputs

**Static findings.** [Python title-analysis models](../../../../goodwatch-flows/windmill/f/dna/models.py) require 74 `CoreScores`, `highlight_keys`, essence text/tags, anime/production information, broad advisories, social suitability and viewing-context flags. `create_fingerprint` orders scores using the Python model's field order. [Webapp score keys](../../../../goodwatch-webapp/app/server/utils/fingerprint.ts) repeat the V1 vocabulary and order. [Generation vector persistence](../../../../goodwatch-flows/windmill/f/dna/generate/vectors.py) derives vectors from currently stored scores with a conditional update; it does **not** call an embedding model.

**Proposed changes.** Keep a validated canonical title-analysis document; treat concise model output as one transport adapter into it. Version the vocabulary, measurement rubrics, scope and generation provenance. Validate both structure and semantics before publishing. Maintain stable IDs such as `themes.survival_centrality` versus `narrative_engines.survival_centrality`; leaf-only flattening collides. Display labels, measurement metadata, aliases, applicability, spoiler rules and selected feature profiles belong in a shared registry outside repeated LLM output.

Preserve `essence_text`, `essence_tags`, valid stable `highlight_keys`, advisories and structured companions. A score-only provider requires a separately assessed prose/annotation stage; its score-call price is not the whole-analysis price. Highlights should reference known assessed concepts, avoid spoilers and explain representative traits. Do not derive every highlight from the numerically largest score across incomparable scales. The current [full schema](../schema.json) describes the earlier verbose document, so concise generation needs an explicit matching schema/adapter.

The compact proposal uses null for unknown or inapplicable and omission for unassessed. A canonical state model must retain those distinctions if consumers require them; a bare null cannot recover why it was null. Evidence coverage also matters for hard exclusions. Scales may become ordinal, categorical, binary, duration or count: do not force those through the existing integer-score validator or one universal vector normalization.

As a sizing illustration only, replacing the 74 score bytes with 547 one-byte values would grow the base row from 101 to 574 bytes, about 5.7×. Typed measurements and evidence have different storage requirements; this is not a proposed layout or a measured runtime cost. Snapshot publishers, decoder validation, key order, masks and all fingerprint consumers must migrate together.

## Query interpretation, filters and discovery

**Static findings.** [Search interpretation](../../../../goodwatch-webapp/app/server/combined-search/reading-retrieval.server.ts) asks want/avoid probability questions for each V1 score, then decodes weighted preferences. A naïve 547-key expansion produces 1,094 questions per request. Search also uses text, labels, entity/reference profiles and title lookup; the [ranker walkthrough](../../../prototypes/search-arena/results/simplify/HOW-IT-WORKS.md) and [implementation](../../../implementation/search-ranking/README.md) describe those separate signals.

**Proposed changes.** Retrieve relevant concepts/groups before detailed interpretation, or test another structured constraint plan. Preserve hard versus soft constraints, negation polarity, same-character/same-scene binding and scope. “Cars,” “chases” and “black and white” on the same title do not prove a monochrome car chase. Existing soft label penalties are not certified content absence. Include coverage/unknown policy in strict filters rather than treating a missing score as low intensity.

**Static findings.** [Shared title filter](../../../../goodwatch-webapp/app/server/title-filter/index.server.ts) powers Discover, Watch next and Explorer over snapshot/availability data, with other lookups for similarity/people/legacy filters. [Mood rules](../../../../goodwatch-webapp/app/domain/moods.ts) and [theme/style rules](../../../../goodwatch-webapp/app/domain/themes-styles.ts) use V1 names, thresholds and finite masks. Their score accessors can substitute zero for missing attributes.

**Proposed changes.** Reassess rules against V2 definitions and measurement types; retain stable user-facing filter IDs/URLs where meaning is preserved. Rebuild memberships, masks, counts and caches. Examples: overall humor can replace maximum subtype humor; future setting differs from advanced technology; graphic explicitness differs from grotesque aesthetics. Missing-aware comparisons need particular care for upper bounds (“not bleak”) and exclusions. Extend finite mask layouts deliberately if new discoverable categories outgrow their capacity.

Holiday/culture/place/era, intended audience, scoped representation and documentary/animation presentation already have homes in the full design. Preserve them through concise companion outputs or catalog joins. Their absence from `attribute_groups` is not authorization to drop them. Runtime, credits, original/available languages, streaming offers, ratings and progress remain independent catalog/user facts.

Do not give aliases, parents and child concepts several independent similarity votes. Sparse shared absence is not positive topic similarity. Changing scales and feature counts requires judged retrieval/recommendation comparisons, not only array-length and schema checks.

## Migration and verification sequence

1. Freeze canonical IDs, typed measurements, assessment states, source/scope and concise output adapters; keep V1 contracts readable.
2. Generate a representative V2 sample with complete companions; judge evidence quality, highlights and difficult exclusions before bulk backfill.
3. Publish V2 alongside V1, with consistent score/vector/artifact/snapshot versions and rollback. Never overwrite a 74-dimensional vector with an incompatible shape.
4. Prototype selected search/filter/display consumers, then related/Explorer/Taste/personal-order derivations. Make mixed-coverage fallback explicit and observable.
5. Verify publisher-to-reader parity, counts/filters, exact-title guardrails, judged search/recommendation cases, cache invalidation, missing/spoiler behavior and representative pages. Measure memory, backfill throughput and fresh/cached latency before rollout.

The [discovery evidence index](discovery-evidence-index.md) identifies reusable benchmark contracts, scripts, measured results and synthetic cases. Existing V1 benchmarks help choose evaluation methods; they do not certify V2 quality or allow direct extrapolation of generation/search cost.
