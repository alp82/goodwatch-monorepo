## Compatibility boundary

[ADR 0011](../adr/0011-search-runs-as-a-role-of-the-webapp-image.md) allows explicitly deployed search roles to lag the page image. The proxy routes exactly `/api/combined-search` and `/api/command-palette`, with any query string, to the search roles. Page/Remix loaders, preference saves, preview, Discover, related maps and tracking APIs remain on page instances. Check `SOURCE_COMMIT` for both roles; never assume a page deployment updates search.

Verified the pre-language contract at `ad44d748^` against current code, rather than assuming every historical release is compatible.

## Durable rollback

- `gw_loc` is an extra cookie. Older auth/cache parsers identify auth cookies separately and ignore this name. Old pages use their browser/legacy country behavior and English media; they do not erase the cookie. Rolling forward restores the saved choice until its normal expiry.
- `media_preferences_v1` is one extra `user_setting` row. The verified old `_convertSettingValue` skips keys absent from `UserSettingsSchema`, so JSON is not parsed as an old setting and does not crash settings reads. Old code may continue updating `country_default`; it does not delete or overwrite the pair. On rolling forward the saved pair wins over that legacy row. Do not silently mirror/delete the pair to make old UI appear current.
- Translation tables are additive and are not owned by webapp rollback. Revert the image, **not the data/schema**. Keep season/episode translation rows, old legacy country rows and saved pair JSON. Do not run DOWN/DROP/truncate, wildcard Valkey deletion or a preference cleanup.
- An older search role may remain through page rollback: no-opt-in search/palette requests return English. If desired, roll search back separately, one role at a time using the existing deployment procedure. A complete page rollback requires reloading open tabs before using the older settings UI.
- Guest/member saves retain atomic pair/OCC/request sequence boundaries in the new page code; undo is the same boundary. Never try to roll back preferences by rewriting two legacy rows.

## Cardinality and limits

Let `L=14`, `C` be active country values, `U` be distinct canonical URLs, and `B` be distinct requested title-ID batches in a TTL window. Keys are created on demand, not prewarmed as a language/country product.

| Cache | New growth | Lifetime and bound |
| --- | --- | --- |
| Anonymous page HTML | At most `L*C*U` for one render/header-policy/build/host/asset combination; further policy/build combinations multiply independently. Saved cookie revisions, device/client IDs and browser-vs-explicit preference provenance do **not** multiply keys. | Per process: **128 MiB / 2,000 entries**, LRU; 4 MiB compressed entry, 8 MiB raw HTML; admission map 20,000, repeat threshold 2, bounded flights/waiters/refreshes. Response cache policy controls fresh/stale; deployment may set `PAGE_CACHE_MAX_FRESH_SECONDS=1800`; `PAGE_CACHE=off` is the existing switch. |
| Canonical details | Country-sensitive offers already multiply by `C`; new wrapper forces language English in this cache, so no new 14× detail-value copies. | 12h fresh + 12h stale, physical 24h; missing-title marker 60s and title-only. |
| Media source overlay (`media-overlay-title-v3`) | At most `14*T`, **not** `14*C*T`; per-title/type/full-locale entries are reused across overlapping batches. | 30m/no stale; 200 missing IDs per query batch; **64 KiB maximum serialized value**, 4 MiB serialized memory / 2,048 LRU entries per process. Only the winning localized poster and canonical paths are cached. In-flight source work coalesces per title/locale. One deadline-bounded MGET and a write pipeline serve each batch; locale hash tags make these cluster-safe. |
| Episode text source (`episode-text-show-v3`) | Per kind/show/full locale; complete show sources and misses are reusable across grids/groups. Presence remains one constant key. | Presence 5m/no stale; rows **30m/no stale**, **4 MiB/value**, **16 MiB serialized memory / 128 show entries** per process. At most one table query per missing-show batch; returned text is filtered to proved requested episode IDs. Oversized show values are not cached. English performs no source/presence read. No unused season text read is performed. |
| Preview (`localized-title-payload-v5`) | Up to `14*T` live named-title keys plus `T` canonical-bot keys; no country/private state dimension. The render-policy bit prevents a bot from receiving cached English localized artwork. | Versioned namespace, 30m/no stale; healthy public response 30m; read-error fallback is private/no-store with no Valkey write; bot answers private/canonical. New browser preview URLs carry `presentationVersion=5`, and TanStack keys use `media-title-v5`, avoiding old cached script labels. |
| Canonical cards / portrait / maps / search reading/ranking | Language is applied after these reads. No new language product inside canonical caches. | Cards 6h; portrait 10m; map neighborhoods 24h fresh + default capped 1h stale; existing bounds stay in place. |
| Pair-aware settings | One additional per-member versioned projection plus the old namespace during mixed deployment. | 5m/no stale, reset markers; presentation saved-record reads use a separate 15s/2,048-user memo, with no stored raw JSON; mutations/CAS remain uncached. |

The repository's country-name resource has **250** entries: illustrative `14*250=3,500` variants per URL before policy dimensions. Country normalization intentionally retains existing two-letter behavior; the syntactic ceiling is `26²=676`, or **9,464** pair variants per URL. The actual selectable `country` table was not broadly scanned. For 10,000 distinct URLs and 250 countries the theoretical product is 35 million, but page admission, the 2,000-entry/128-MiB cap and request demand prevent allocation of that product. At 64 KiB per admitted HTML variant, 2,000 entries use about 125 MiB before accounting overhead; the byte cap can evict earlier.

Valkey nodes have repository defaults **7 GiB maxmemory / volatile-lfu** (`goodwatch-cache/valkey.conf`), and node compose can override `REDIS_MAXMEMORY`. All new source entries have an expiry and are eligible for that eviction policy. TTL is a lifetime bound, not a per-cache key-count budget. At illustrative `T=10,000` distinct titles/30m and 4 KiB/compact source value, the language ceiling is 140,000 values (~547 MiB before overhead), shared across countries; actual value size and locality must be observed after deployment. Do not raise global limits or prewarm all pairs on the strength of this estimate.

## Localization read errors and cache admission

Optional title/episode translation reads are deadline-bounded at **1,000 ms** (`MEDIA_OVERLAY_TIMEOUT_MS` overrides only localization). The Crate adapter also receives that timeout and abort signal and destroys a stalled socket; existing canonical reads/writes retain their ordinary deadline. A title/episode operation stops making subsequent source reads after its first error. Missing translation rows from a successful query remain a cacheable per-field fallback. Failed queries are never treated as successful absence.

Request/dependency health is tracked server-side without adding failure/device state to public DTOs or cache identity. The generic Valkey cache refuses error-derived payload writes, including shared in-flight runs and background refreshes (which retain their last healthy stale value). Healthy independent canonical/table-metadata entries can still cache. Responses built from failed localization use `private, no-store`; early streaming shells with pending optional localization are conservatively no-store. Page-cache admission checks at offer and after compression reject failed/pending requests. The same request health wrapper remains active with `PAGE_CACHE=off`.

Preview uses **v5** for Valkey namespace, URL `presentationVersion` and TanStack key. This bypasses English fallback entries/CDN/browser responses previously cached under v4; do not purge translation/preference data. Source caches retain v3 because failed source loads already reject and never publish rows. Origin HTML remains separated by build identity. Search-role HTTP stream policies remain private/no-store; the cache guard takes effect when each role receives the new image. No deployment was made here.

## Read-only production verification after deploy

Use named titles and GET/HEAD or bounded SELECTs. GETs can warm ordinary caches; do not confuse that with a preference/data write. Do not use a POST search for verification: combined search writes history and can invoke paid interpretation.

- Inspect `/health/ready` and role/commit health using the existing deployment runbook. Check the proxy still routes exactly the two search paths, including query strings; direct role checks use the existing authenticated operator path.
- GET a small title sample (e.g. Breaking Bad, Spirited Away, Sword Art Online) with guest language cookies/headers for `en,de,ar,ja,zh-Hant`, keeping country fixed. Check media field `lang`, script-compatible title fallback, canonical hrefs and unchanged episode ratings/membership. GET preference/bootstrap is read-only for every account: GET never adopts or writes an account row. Automatic adoption is confined to POST `/api/media-preferences/session`; do not invoke that POST during read-only verification.
- GET `/api/command-palette?q=breaking` without opt-in (English), then with `displayLanguage=de` (localized or English fallback). A lagging old role may return English in both cases, with no error. Do **not** POST combined search to prove localization; use the tested fixture contract plus role version/readiness.
- GET `/api/media-title?type=show&id=1396&displayLanguage=de&presentationVersion=5`; expect entity present even before translations. Probe a valid uncommon unsupported explicit language once: it normalizes to English.
- Bounded SELECTs for named show/season/episode IDs confirm translation keys and nonblank source text. Verify canonical episode rows/IDs and counts against the same named sample; absence of translation is not an episode-existence signal. No global coverage COUNT, broad scan or repair write.
- Observe existing page/data-cache metrics and bounded `INFO memory`, `INFO stats`, `INFO keyspace` / exact-key TTL checks through the operator procedure. Compare evictions, hit rate, refusal/entry/byte gauges and Crate timeouts with the predeploy baseline. Do not use `KEYS`, broad SCAN or a mass warming script.
- Wait out the five-minute table-presence TTL after schema creation if a node previously cached absence. Ingestion source visibility can also wait for Crate refresh and the 30-minute media/preview cache TTL. Use an owner-approved normal restart/cache reset only when needed; that is a separate mutation checkpoint, not a read-only probe.

## Rollback steps

Stop/leave ingestion unscheduled; it is additive and independent of presentation. Redeploy the last known page image using normal asset continuity, optionally then older search images serially. Reload browser tabs. Leave cookies/account JSON/translation tables intact. Canonical English responses and existing country behavior are the safe fallback. If only cache behavior is suspect, the existing `PAGE_CACHE=off` is available at an operator restart; do not delete persisted choices or translations.

Historical phase-5 [verification artifact](media-language-rollout-verification.json) records its exact commands/counts, diagnostics and changed files. At that snapshot, typecheck matched a clean merged-HEAD baseline (212 existing diagnostics; none added). Python passed 1,220 tests with 51 skips. Both full Node runs had failures in unchanged timing-sensitive suites; every failing case passed in isolation, and changed media suites passed. The full suite is not claimed green. Browser checks belong to the UI thread; no build or additional dev server was started for this prep.


## Review fixes (2026-10-14)

- Index canonical/translation/poster sources once per call; linear winning-poster selection. SQL reads only selected base-language posters or canonical paths. English-equivalent canonical projections do no source IO. Completed overlays are reused only when field scripts/provenance remain valid, avoiding duplicate work at card + route boundaries.
- Explorer APIs require explicit `displayLanguage`; private page SSR follows live language. Both are capped at 200 unique titles per response, preserve the canonical tail, and never seed a different-language client cache with canonical SSR data.
- Crawler Discover initial data and movie-collection prefetch use the client's **en** key while the payload stays canonical.
- Account adoption is a POST session-establishment operation, not a root GET side effect. Cookies identify their source (`sourceUserId: null` for guests, account ID for members). Only proven guest-origin cookies are adopted; older unmarked cookies remain usable by guests but are not silently adopted into accounts. Guest cookies are emitted only by an explicit Keep of the whole pair; the unused `countryExplicit` flag was removed. Session establishment is remembered per tab/user and returns `{changed}`; only changed preferences or identity revalidate loaders. Owned cookie revisions that differ from the short account memo force a fresh read before cookie reconciliation.
- Tracking keeps one mutation queue per user/show; localized reads change presentation without replacing pending optimistic marks.
- Script checks normalize locale case and disregard modifier-only evidence such as tatweel. Preview server/browser namespaces are versioned, and persisted browser display values are rejected when their language claims contradict their text. Highest-rated person stats retain field presentation and canonical title identity.
