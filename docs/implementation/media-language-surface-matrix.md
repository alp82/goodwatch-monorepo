## Read and cache contracts

`app/server/media-overlay.server.ts::overlayTitles(rows, language)` is the production boundary; `utils/media-overlay-core.ts` contains the pure resolver and injectable batched reader. A canonical movie/show row keeps its stable ID, extra numeric ranking/matching fields and order. Results are copies. Each nonempty **deduplicated batch of at most 200 work IDs** reads one canonical UNION statement (movie/show once each), one `translation` statement and one bounded `media_image` statement. The latter reads all poster language tags for these work IDs so canonical-poster provenance does not depend on a caller's input shape. No title-by-title translation calls. Source cache: `media-overlay-v1`, sorted work keys + bounded language, 30 minutes, no stale window. Empty batches read nothing. Failed source reads log and return canonical fallback; they do not fail the entity or populate the source cache with the failure.

`presentation` carries the selected language and `{language, source: localized|original|canonical, fallback, translationLocale?}` independently for title/poster/overview/tagline. Nonblank compatible text candidates follow the decisions' region order, per field. Posters select matching **base** language deterministically by vote average/count/width/path; neutral/unproved language is `und`. `canonical_title` preserves stable links. Missing rows, blank fields and unknown poster language neither discard nor hide a work. Every normal presentation call is after matching/ranking/pagination. The server graph adapter handles the existing snake/camel aliases, typed work keys and TMDB `id`/`type` rows; person/collection identities and numeric fingerprint inputs remain canonical.

Canonical display memory/Redis (`title-card:v1`), details-movie-v2/details-show-v3, Qdrant neighborhoods, canonical library names, portrait source caches and Explorer fingerprint/geometry pools stay language neutral. Localized values are applied **after** those reads and cannot mutate the stored objects. The show details shape version changes because seasons now retain stable TMDB IDs and canonical text; related-by-category's canonical cache version changes because flattened members now retain work IDs. The localized preview cache is `localized-title-payload-v2` keyed by type + canonical ID + language. API URLs carry `displayLanguage`; affected TanStack keys, related/collection SSR hydration keys, browse initial-data keys, Explorer engine keys and browser display caches include/check that same language. No display language enters the paid search interpretation or ranker key. Existing country/streaming filters remain independent. Cards preserve their thin field projection rather than acquiring unconsumed synopsis text.

Pages derive presentation from the recipient's effective context; a pasted page `displayLanguage`/old `language` query does not create a localized address or override that context. Public title APIs accept an explicit bounded `displayLanguage`, defaulting to English for old callers; private live APIs can fall back to effective context. A title link's canonical slug comes from `canonical_title`, not a translated label. No hreflang or localized canonical URL is introduced.

HTML origin keys retain the normalized effective pair and add a **canonical/localized render-policy dimension**, because live English posters can differ from plain canonical images. Named crawler responses use canonical content and are kept private to any front cache; the origin can still cache them separately. Saved-cookie humans keep normal shared origin caching. No edge HTML cache/worker setting GW-Cache-Identity is implemented in this repository; [cache identity](../cache-identity.md) records the deployment requirement for any future edge.

## F inline preview API for the UI thread

The merged UI `MediaText` component accepts `{value:{text,lang}}`; adapt a scalar field with its `presentation.<field>.language` (or `mediaFieldLanguage`). This backend keeps existing scalar contracts intact.

Pure shared types/builders: `app/utils/media-presentation.ts::{LocalizedTitlePayload,LocalizedTitleResponse,localizedTitleUrl,localizedTitleQueryKey,mediaFieldLanguage}`.

```http
GET /api/media-title?type=movie&id=603&displayLanguage=de
Cache-Control: public, max-age=1800, s-maxage=1800
```

```ts
{ title: {
  media_type: "movie" | "show", tmdb_id: number,
  canonical_title: string, title: string, poster_path: string | null,
  overview: string | null, synopsis: string | null, tagline: string | null,
  presentation: MediaPresentation
} }
```

This GET writes no preferences, contains no account/country-offer state, and uses only type/ID/language. Unsupported explicit language normalizes to English. Invalid type/ID → 400 no-store; missing **canonical entity** → 404 no-store; missing translations → 200 with per-field fallback. IDs pass the existing canonical identity map. Guard/cancel stale preview fetches on title/language changes; compare the returned ID and `presentation.language`. Keep/Undo still use the existing atomic preference endpoint. `overview` and `synopsis` are equivalent here for compatibility with the current details contract.

## Season / episode ingestion dependency

`episode-text-overlay.server` supplies injectable per-show and cross-show batched adapters. They enumerate **only canonical existing membership** and match translation rows by `(show_id, stable TMDB id)`. `show-tracking.server` builds all ratings/coverage from canonical names first, then overlays its returned episodes. Reviewed presentation grids retain TMDB IDs through wire packing; only these IDs can select localized names. Equal IMDb/TMDB season/episode numbers are never a join. Unmatched IMDb tooltips retain canonical text with `und` language. A metadata lookup limited to the two exact source table names is cached for five minutes; no speculative SELECT is issued against absent translation tables.

The next ingestion step must provide `doc.season_translation` and `doc.episode_translation` with `show_id`, `tmdb_id` (TMDB season/episode ID), `language_code`, `country_code`, nullable nonblank `name`/`overview`; suggested PK `(show_id,tmdb_id,language_code,country_code)` and clustering by show_id. Source version/fetched-at and complete per-entity locale cleanup should be added by ingestion. A language-filtered response must never delete other languages as if it were a complete catalog. The read side auto-detects these names/fields without a schema write here. Metadata presence discovery may lag table creation by five minutes.

Season rows in the catalog details now retain name/overview/stable ID. The show page applies their text overlay only **after** its canonical/reviewed grid has selected membership; `details.server::presentShowSeasonsAfterAlignment` is that boundary. Reviewed regrouped display-season buckets do not carry a proven canonical season ID, so their names/descriptions are **canonical by release policy**. A future bucket identity needs an explicit mapping-owned bucket key, with membership hash as a separate source revision; see the text-production runbook. Attaching a canonical season translation by display number or to a split/merged bucket would misdescribe it. Existing English season-number interface labels remain. Episode rows/open descriptions/Next readers have overlays ready. Upcoming rows now retain their canonical TMDB episode ID too and share the cross-show text batch with Next rows; the additive bounded translation companion can now produce their source rows, but has not been run. No episode-description canonical backfill is repeated. Existing `episode.overview` is already present. The alignment plan exists in this checkout and was consulted; this code does not load or depend on the document at runtime.

## Canonical library search and sort evaluation

Current `my-library.server::titlesOf` reads canonical `title` only, per-ID memory cache six hours; it does not read `translation` or `alternative_title`. `domain/my-library::libraryOrder` folds NFD diacritics/case, does substring matching on canonical titles, and Title sort removes leading English `the|an|a`, then uses the existing stable key tie-break. Pagination/counts are computed from that canonical set before the display overlay. Thus a German display of “Spirited Away” does not make “Chihiros” a library match or reorder the Title pages. This is the orchestrator's decided release behavior, superseding the older research's proposal to localize Title sorting. No locale collation or ranking change here.

Main search/palette continue their current canonical/original-name indexes and TMDB fallback query routing, and share-title search keeps current canonical name matching. Localized alias matching needs separate coverage/evaluation, including multiple country aliases and script/region distinctions; it is deferred as agreed. Display overlays are not evidence that localized names are findable. A hand-written non-English legacy TMDB retrieval parameter can produce an unproved fallback language for a work absent from Crate: these fields carry `und`, rather than falsely claiming English. Available canonical Crate fields take precedence in that case; no extra upstream request or entity hiding is introduced.
