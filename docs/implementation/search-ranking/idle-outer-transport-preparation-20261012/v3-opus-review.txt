## Non-blocking

- **N1 covers schema, not value, before creation.** A well-formed but wrong identity still has private inputs read and a manifest-less stage written before the mismatch is detected in `_stage_bound`. The stage is unusable, and it is documented as consumed.
- **Exit 4 is still shared with pre-receipt handshake refusals.** EOF, timeout, wrong GO, flags and origin mismatch call `os._exit(4)` directly. No receipt exists on those paths, so nothing can verify. The doc sentence is accurate only for exceptions.
- **One assertion pins a race outcome.** In `test_pidfd_acquisition_failure_retains_unknown_receipt_without_numeric_signals`, exit 5 depends on the entry's ready-write hitting an already-closed gate. If the entry wrote first it would read EOF and exit 4. That would need the parent stalled for a whole interpreter startup, but if R1 shows this test failing with 4, it is this race and not a code defect.
- **The "partial" receipt is complete bytes plus a simulated post-write failure.** A truncated receipt is not separately exercised; it would fail JSON parsing.
- **Carried from V2, unchanged:**
  - The entry accepts root with `reviewed-preparation`, so inactivity means "no shipped caller".
  - `_verify_stage` and the final `durable` can raise raw `OSError`.
  - Inheritable descriptors beyond 0-3 are not closed before exec.
  - `test_production_rejects_unprivileged_fixture_without_spawning` is vacuous.
  - The cron redirect target is not cross-bound to the phase log (unchanged `idle_lease.py`).
- **Still zero execution, by design:** the `stage_reviewed` success path, the `reviewed-preparation` branch of `_verify_stage`, the root branch of the entry's `verify`, the runtime before/after comparison, and real-host `hierarchy_root` behaviour.
