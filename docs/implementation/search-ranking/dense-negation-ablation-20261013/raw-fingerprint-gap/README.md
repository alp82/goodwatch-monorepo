# Raw fingerprint subset: concrete next evidence

The current published index has 42,934 rows. A full aligned 74-component Float32 raw-score matrix is 42,934 × 74 × 4 = **12,708,464 B** (12.12 MiB). It adds a small local input compared with the existing dense matrices. This is an input-size estimate, not measured runtime, production capacity, or a quality PASS.

The original nonreference ranker starts with an exact `fingerprint_v1_raw` Dot top-500 request using the stored reading's original 74-component vector. The order is `VALID_FINGERPRINT_KEYS`, equal to Python `CoreScores.model_fields`; absent query weights become zero. The query weights retain the original reading decoder's selected `2 × (want − avoid)` values and thresholds. Do not normalize the title raw score array or the query vector for this signal. `fingerprint_v1` cosine would be a different signal. The original fixed fingerprint contribution is `0.48 × z(rawDot)`.

A meaningful next offline comparison intersects every variant's title population with the same observed raw-vector validity bitmap and original query mask. For each eligible query, form the union of the local dense top 500 and raw-dot top 500 (at most 1,000 IDs), rescore **all** union members with each available signal, and compute population z-scores over that same union. Then compare the fixed dense/negation/prior signals with and without the existing `0.48 × z(rawDot)` contribution. Keep all other available weights unchanged. This common-union comparison isolates the added fingerprint score; separately reporting how many fingerprint candidates are new identifies retrieval effects. The already frozen dense-only top-500 study is a different candidate-pool experiment, not a silently interchangeable control.

The production hybrid additionally unions BM25, facets, coverage and reference lists. A dense/raw-fingerprint union still omits those signals and candidates, final title blending, catalog delivery and taste. The extracted **current catalog** scores cannot attest Qdrant publication or the historical index epoch. Current adult/vote drift and invalid/missing raw rows must remain explicit and identical across compared variants. The bounded catalog reader is a separate prepared engineering step, not executed by this memo.

## Existing grade gap, before raw scores exist

Across the 94 graded queries in the frozen 101-query English/nonreference study, the existing judgment file contains 1,763 grade-2-or-3 query/title pairs. Of these, 1,498 are present in the current title index, and 1,496 pass their current bound mask. Of those eligible pairs, **710 are absent from the frozen dense-only top 100**. These are output-level gaps, not proved misses from the dense top-500 candidate pool: the completed study did not retain all 500 candidate IDs, and it will not be rerun to manufacture that proof. New raw retrieval may recover some gaps, but no count is predicted before actual dot scores are available. The 265 relevant pairs missing from the current index cannot be recovered by any raw-score subset restricted to those index IDs.

The familiar failure examples impose different limits. `core-04` has three known grade-2-or-3 indexed/mask-eligible titles, all absent from dense top 100; raw fingerprint might supply a useful test there, but an authoritative typo/title lookup is a separate mechanism. `h5-19` has no existing grade-2-or-3 judgment at all, so the observed three bad top-five titles cannot establish a judged-positive recovery target. `ho2-09` has one grade-2-or-3 judgment, outside this current eligible index population; this bounded subset cannot recover that judged target. Unjudged alternatives remain unjudged, not bad and not implicitly good.

No weights, acceptance bars, current-final overlap, public query encodings, app code or production searches are added here. Full production latency remains unmeasured.
