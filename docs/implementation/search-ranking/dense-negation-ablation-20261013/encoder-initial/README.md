# Public corpus local encoder cache

This cache was computed once locally from 168 authored public captures exported byte-for-byte from commit `965bfb99c795e8eb602746d69fd53e97ca36cd3b`. The capture tree includes an `index.json`; it is not a query capture and was excluded. No private history, Jev call, application search, production connection, model download, or host control was used.

The worker is the original `query-encoder.worker.js` from deployed source commit `927d38b2cca815f02a0b1636ec06f63c24603396`. Six locally cached files passed independent streaming SHA-256 and size checks against that source's pins before execution and again after completion, with stable descriptor device/inode/size/mtime/ctime. Original TypeScript parsing helpers were transpiled using the existing local TypeScript installation; the JSON negation import was replaced with its frozen JSON literal. The model specification module was transpiled to read its static `QUERY_MODELS` export; its download functions were never called. Source originals and generated derivatives are separately hashed.

The worker ran with two intra-op threads and one inter-op thread, using its original sequential queue. Each public capture received exactly one batch. The request model was selected from stored `language.detectedNonEnglish` or the original `looksForeign(text)` helper, using stored `language.text` where present. Texts were the deduplicated raw text, `splitNegation(text).positive`, and negated clauses. This augmented cache is **not an exact `prepareSearch` EARLY request**: index-dependent spelling, title/entity reference resolution, and entity-intent residuals remain unbound. No prepared-search parity is claimed. It supplies reusable vectors if later bound resolved text exactly matches a cached string; otherwise a separately authorized cache addition would be needed.

The run completed 168 corpus batches: 156 English and 12 multilingual, with 196 distinct English vectors and 21 multilingual vectors. All returned vectors passed dimension, finite-value, and unit-norm checks. Worker startup took 8,282.74 ms including its original six warmup batches (12 fixed warmup texts). The sum of observed corpus batch wall times was 16,905.50 ms; median 76.33 ms, p95 231.32 ms, maximum 594.49 ms. These are local cache-construction observations, not production or end-to-end search latency evidence. Startup is separate from corpus timings. The corpus batching ceiling excludes the worker's unchanged internal startup warmups.

`query-vectors.json` maps model name and exact public text to Float32-derived numeric vectors. `encoding-results.json` records the requested public text inventory and per-batch timings. `validation.json` records vector checks and postflight pins. `invocation.json` records Node and dependency versions and package metadata hashes; no deployment dependency equivalence is inferred. Dependencies resolve through the existing webapp `node_modules` symlink, whose installation was not changed. The freeze manifest excludes that symlink tree and explicitly binds relevant dependency entrypoints, package metadata, and ONNX native files separately.

The harness uses fresh output files and is not safe to rerun into this evidence directory. This run has already spent the initial 168-query batch allowance. Later index integration must inspect the cache first and document exact text coverage rather than rerun it blindly.
