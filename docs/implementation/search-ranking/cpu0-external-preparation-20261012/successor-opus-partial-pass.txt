## Residuals (nonblocking)

**A. Cleanup still cannot signal the consumer when the clone is not attestable.**
- `registration.py:123` calls `lifecycle.attest(NEW)` before any signal; `prior()` and `pair_snapshot` call it too.
- `attest` requires exactly two cgroup members (`lifecycle_cpu0.py:280`) and a running container.
- If a failure lands while the clone is stopped or a helper child is joined, all three reads refuse and no TERM is sent. Only the handoff hash is observed.
- I have not re-read the controller phases to confirm when a helper is joined.
- This follows from your requirement to keep outside-source protection at cleanup. The result is reported unknown.

**B. A failure frame after a torn private line loses its reason.**
- `executor.py:180-181` forwards raw 64 KiB chunks, so a mid-stream failure (for example `producer_private_total_bound`) can append the frame to a partial line.
- `json.loads` at `private_pipe.py:171` then raises, and the outer reports `outer_guard_or_runtime_failure` without the remote evidence.
- Fix: have `bootstrap.py:80` write a newline before the frame on `producer-stream`. In the pipe, on an undecodable line, check whether the next complete line is a valid failure frame before raising.

**C. Blocking stdout writes on the producer host are not lease-clamped.**
- `private_bytes` and the registration `print` (`executor.py:180-183`) can block past the lease if the local side stops reading without closing.
- In the normal case the local kill at the deadline gives EPIPE and cleanup runs. A silent network loss would leave the write blocked.
- The remote lease also starts later than the local clock by SSH latency.
- Fix: arm `signal.setitimer` for the lease in `producer-stream`, with a handler that raises `producer_global_deadline`.

**D. The cleanup census now runs outside the control lock.**
- `executor.py:135-146` reads writers and the pair before `acquire_control` (`:150`); the previous code read them under the lock.
- `proc_controls` does not depend on the lock, so the census itself is sound. The reported `pairSnapshot` can differ from the one inside the committed handoff.
- Fix: on the no-refusal path, repeat `prior()` after `acquire_control`.

Smaller points:
- An identity mismatch at cleanup leaves the owned container running and reported `containerGone: False` (`producer.py:216`, `:385-386`).
- `cleanupAttempted: False` is reported even if a stop was sent and then failed (`producer.py:216`).
- Secondary census errors keep only their reason code, not `currentWriterEvidence`.
- `rpc.py:73` passes remote failure dicts through without the closed-shape check the pipe applies.
- An audit timeout surfaces as `outer_guard_or_runtime_failure`.
- `producer-confirm` uses its own 60-second lease.
- `primary_fixture` is in the production reason list.
