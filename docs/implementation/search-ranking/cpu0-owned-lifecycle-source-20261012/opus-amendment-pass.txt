## Caveats (non-blocking, all fail closed)

**Can spend the one-shot real stop with a false refusal:**
- The post-signal Docker inspect is still a single sample. If dockerd has not yet taken the container lock for the exit event, the row says `running: true` and the stop is recorded as unclean. I can't quantify this; a re-inspect loop inside the remaining budget would close it.
- A stop that finishes near 20 s leaves no budget for that inspect and is recorded as a timeout.
- `birth_gone` still catches only `FileNotFoundError`; a reap between open and read of `/proc/PID/stat` escapes as `lifecycle_guard_or_runtime_failure`.

**Evidence edges:**
- If `require_lock` fails after `clean_state` passes, no receipt is issued. The failure evidence does retain before/after and timing, with `clean: False`.
- `lifecycleCleanupFailure` is a single slot: a pidfd-close or lock-scope failure overwrites `lifecycle_docker_cleanup_failed`. `lifecycleDockerCleanupEvidence` survives separately.
- The inspector's cleanup `except BaseException` can absorb a `controller_interrupted` raised during cleanup into an annotation.
- The receipt exists only in emitted rows. An emit failure, or an interrupt between `graceful_stop` returning and the assignment to `stopped`, loses it.
