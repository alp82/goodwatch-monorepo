### Non-blocking findings

1. **Missing composition test for the state this amendment makes likelier.** No fixture covers: OLD stops cleanly below 5 GiB, then `host()` refuses at `before_create` with `engine.request` never called. `test_external.py:239-258` always passes `mock.Mock()` for `before_create`. The ordering is correct by reading `setup.py:424-426`, but it is untested.
2. **That state is terminal for a rerun, by design.** `stage_absent` (`setup.py:352`) runs before the full host check, so the admission directory already exists when `host()` refuses. A rerun then stops at `setup_fresh_public_scope_required` (`setup.py:325-326`). This matches "failures remain terminal" but is not spelled out in `SHUTDOWN-ADMISSION.md`.
3. **A successful shutdown admission leaves no public trace.** The `cpu0-old-shutdown-host-admission.v1` evidence is discarded on success and is absent from `cpu0-external-setup-result.v6`. The same was true of the old 5 GiB evidence, but a successful result now does not disclose that the stop was admitted under 2 GiB.
4. **One vacuous assertion.** `lifecycle.graceful_stop.assert_not_called()` at `test_shutdown_admission.py:53` cannot fail, because `old_admission()` never calls `graceful_stop`. The real proof is the fifth test's `call_count == 1` through `run_setup`.
5. **Slight wording overreach in the README.** `README.md:54` says every CPU0 runtime admission requires "more than 5 GiB". The frozen `host_available` refuses on `available<floor` (`controller_cpu0.py:279`), so some runtime checks admit exactly 5 GiB. The code is unchanged; only the sentence is imprecise.
6. **Test name.** `test_real_setup_shutdown_refusal_never_stages_creates_or_starts` exercises an unclean stop, not an admission refusal, and "starts" is covered only because `create_owned_clone` is mocked.
