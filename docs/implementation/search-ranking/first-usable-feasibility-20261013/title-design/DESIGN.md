# Earlier authoritative title/person results: design only

Owner permits a useful provisional result followed by the full update. No approval question is requested. No code changes, host operations, normal searches, query/index blobs or models have been run for this packet. Source authority is deployed927, copied byte exactly. Six private-probe tags are exact-title/native-title/low-vote-title/person/description/reference; bodies are not copied.

## Minimal backend seam

combinedSearch already starts titlePromise and, for streaming callers, initialTitlePromise races its original lookup against a200ms catalog exact fallback. Keep that original promise, lookup bounds, late full title and full reading/rank promise. Do not make another TMDB/catalog query. Create ONE shared titleMatches(initialTitlePromise,policy) immediately after that promise exists, and reuse it as the existing early.titles later; metadata is fetched once and remains authoritative for filters/eligibility. Start a sibling provisional-display promise BEFORE awaiting language/reading, rather than awaiting its delivery before the original reading/rank path starts. Neither sibling cancels/replaces the other.

Reuse titleMatches allowedTitles, withPoster, existing blend(allowedTitles,{results:[]},q,'balanced'), the same original-title lexical rules, IMDb dedup and metadata identity. Provisional lookup-only rows lack description/reason scores and must not invent them. Preserve current title eligibility (ordinary title matches may be below description vote floor) and scoped onlyTitles constraints from readPeople. Reuse already-running shownPeople/peopleToShow for authoritative named people, with its existing scope and failure handling. No independent rawFP/dense ranker.

Only a nonempty actually usable title/person result emits progress. A vague catalog suggestion is not automatically a relevant description answer: model review must resolve whether existing titleMatch lexical>0/person match evidence is sufficient, without silently adopting a new quality threshold. An empty lookup/fallback, metadata-ineligible rows or failed people lookup emits nothing. Pure descriptions/reference phrases without usable literal matches continue to wait for unchanged ranking. No claim of full six-case1.5s coverage.

Add pendingRanking independently of pendingTitleLookup. Early lookup packet has pendingRanking=true and pendingTitleLookup equal the actual lookup pending state; its reading is[] until the existing onReading event arrives. It must not claim completed interpretation. The unchanged full hybrid result has pendingRanking=false; its existing late authoritative title reblend can still carry pendingTitleLookup=true until the final title update. Final completion has both false. A nonstreaming caller receives the same final result as before.

Serialize callback delivery and final/provisional packets so an asynchronous taste callback cannot emit an obsolete lookup packet after the hybrid final. The full computation promise must continue while an early callback/taste awaits. The route's existing sendBatch awaits the already-running searchTaste and applies withTaste to each packet; no provisional bypass of member account/taste or separate lookup. Record firstResults only after the callback enqueues usable rows/people; failed/aborted callback does not record delivery. Keep full computation and actual final delivery distinct.

Expand the existing guarded completion/history region so early progress failures or abortion before reading/ranking completion are not outside its catch. One history write maximum; no provisional write. An actually delivered provisional remains a served incomplete search if final later fails/aborts, with completionFailed/completionAborted and known charge/outcome facts. Paid reading can still complete later; do not fabricate zero charge or an outcome merely because provisional reading isempty. Model review must specify how this composes with existing Jev cancellation/accounting without waiting/retrying new requests. If no usable callback completed, preserve no-success history semantics. Do not switch to a basic final just because a timer elapsed if the original hybrid promise can still finish.

## UX and stream seam

SearchBatch grows optional pendingRanking. Keep reading/provisional/batch stream kinds and full final replacement. search-request accepts reading after provisional until final, which already does not store provisional as final. SearchJourney and Discover currently infer pendingTitleLookup from any partial; replace that inference with independent actual flags for wording. Show a neutral 'Still ranking results' or combined 'Still ranking and checking title matches' state, never falsely 'Title matches could not finish' for ranking failure. Preserve request generation/cache identity, query navigation, ignored stale packets and final-replaces-provisional semantics. People-only usable progress must remain visible; empty rows must not hide the named people. On late failure retain the same-request useful provisional with accurate incomplete status; navigation/new request must not resurrect it. No changed final sort, watch links, taste movement or credit scope.
