## Existing critical path

Round1 batches fingerprint raw exact top500, dense ANN top500 (or multilingual/English union), sparse BM25 and facets/units/reference signals. All consumers wait for the entire batch response, so a fast raw fingerprint/sparse result is unavailable while one dense subquery stalls. The response format has no incremental subquery completion. Splitting the batch would create extra concurrent requests and potentially worsen cold I/O, with no retained cold evidence for an overall improvement.

Round2 scores every union-pool candidate with exact dense/fingerprint and optional negative/facet/reference signals; lesser-known candidates also need payload facts. Exact=true is intentional: the source documents incomplete known-ID scoring without it (789 of1110 in one example). Removing exact, lowering top depths, lowering HNSW search effort or dropping signals is a recall/ranking change, not an equivalent low-risk fix.

Final relevance uses pool-wide z normalization, all weighted signals, then title blending/alternate cuts/reference bounds. A round1 raw/dense top list is not the final hybrid order; emitting it as final cannot preserve relevance. Current progressive results arise only after ranked/displayed results exist and chiefly avoid a pending title lookup. That mechanism does not itself bypass a slow first Qdrant batch.

## Best options within existing representations

**First-usable option:** expose already-running authoritative nonempty title/person lookup results earlier, with the same metadata eligibility, identity deduplication and member taste policy, explicitly provisional and replaced by the unchanged hybrid final result. No local dense scan/raw fingerprint index or new model is needed. This can help literal title/person searches; a pure description with no authoritative title matches remains blocked and cannot be counted as solved. Existing title metadata/taste/display timings and update/cancellation semantics still need reviewed evidence. A placeholder or empty provisional list is not usable. This is a product/source-flow change requiring root's actual design/source/UX review and fresh approved normal-probe packet; no implementation is proposed here.

**Lowest-risk final-computation option:** request-local reuse of scores already returned for identical query-vector/field/filter semantics. Round1 raw fingerprint exact and round2 raw fingerprint use the same reading vector; known scores for overlapping IDs need not be recomputed. Round2 must still score missing pool IDs and merge them before the exact same z/blend. Dense round1/rescore reuse additionally requires score equality under current ANN/quantization behavior and exact query identity; do not infer it from ID parity alone. This avoids duplicate work without a new index/ranker, but the observed slow part is round1, so its plausible gain is downstream milliseconds, not a proven elimination of the cold2–5s tail. Request-local immutable ID+score maps are safer than cross-request/user caches.

Meaningful evidence before score reuse: actual original-versus-merged per-ID score parity and final ordered result parity across existing historical policy variants/reference/negative/mixed/lesser-known cases; incomplete/zero/tie handling and pool-limit coverage; exact score-cache key equivalence; timing specifically separating round1 from round2. Synthetic maps can test composition, but only retained or explicitly reviewed private clone requests can establish actual Qdrant score equivalence. No new calls are authorized here.

**Backend prevention:** preventing allocated graph/vector eviction during backups would target the demonstrated mechanism without relevance changes, but the bounded clone pin path remains unproven. The current fixed max0 lifetime gate/cap cannot be repaired by rebase or a silent retry. Existing backup temp/archive constraints and failed pin trials do not support a new proven prevention remedy. This remains separate from provisional UX and score-reuse optimization.

Recommendation: prioritize truthful reuse of already-authoritative title/person results for first usable on supported cases, preserve the full hybrid final ranking, and treat identical per-request score reuse as an independent small final-path optimization. No existing result reuse can honestly promise1.5s description coverage when no usable authoritative result is ready. Do not market either as a proven Qdrant cold-tail fix.
