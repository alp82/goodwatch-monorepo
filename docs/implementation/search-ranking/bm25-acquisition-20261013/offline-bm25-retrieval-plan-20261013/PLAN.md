# Read-only BM25F recovery feasibility

The original document-side BM25F weights can be recovered directly from Qdrant's stored named sparse vector. This is a source-backed retrieval route, not a claim that current stored values match the pinned index publication. No retrieval has run.

The exact deployed source commit `927d38b2cca815f02a0b1636ec06f63c24603396` uses collection `media_fingerprint_v1` and vector `terms_bm25f_v1`. Its `qdrant-http.server.ts` already implements point retrieval at `POST /collections/{collection}/points` and supports a restricted `with_vector` list. Official [retrieve-points documentation](https://api.qdrant.tech/api-reference/points/get-points) specifies this retrieval endpoint and selector. The method being POST does not make this a point mutation; no upsert/update/delete/query/search endpoints are in the plan. Current documentation is not actual deployed-server version or configuration attestation.

`qdrant_schemas.py` declares no sparse IDF modifier. `embed_titles.py` stores sorted stable term IDs and the saturated BM25F document weights computed by `terms.py`; no title normalization is applied to this sparse vector. Terms are stemmed non-stopword unigrams and adjacent bigrams. Field weights are tags2, keywords2, tropes1, essence1, with frozen field-length averages and float32 arithmetic. The webapp's `bm25Weights` supplies one IDF weight per distinct query term through the pinned term-statistics IDs. `ranking.idf` is `ln(1+(N-df+0.5)/(df+0.5))`. The retrieved sparse values must remain raw saturated weights, not L2-normalized values. These exact nine source files and their SHA/byte lengths are in source-bindings.json.

## Closed proposed retrieval

PLAN.json binds the existing verified current index, all 42934 unique title-table point IDs in exact row order, and its 650794 term IDs / N 42934. Each request contains only the next fixed 500 point IDs (last 434), `with_payload:false`, and `with_vector:["terms_bm25f_v1"]`. The fixed path is `/collections/media_fingerprint_v1/points?timeout=8`. IDs use the existing movie10^12+TMDB / show2×10^12+TMDB namespace. No caller query, private payload, user table or reference-profile collection is involved.

Before and after the 87 sequential point retrievals, two GETs to `/collections/media_fingerprint_v1` retain only server/configuration projections: sparse vector present, modifier absent/none, collection status/count/configuration digest and timestamps of observation. Unexpected IDF modifier or missing sparse-vector schema refuses. These 89 total requests are bounded by 10-second wall time per full response and 600-second overall time, 16MiB per response and 1GiB total response bytes. There are no retries, fallback endpoints, parallel requests or whole-collection scrolls. Per-vector entries≤32768 and total entries≤134217728 are finite refusal bounds, not measurements of actual sparsity. A response exceeding any bound leaves a failed partial artifact and cannot complete. Root reviews a concrete reader plus local malformed/drip/timeout fixtures before any execution.

The concrete reader should use the configured REST origin and existing API key in memory only, with no redirects or output of credentials/address/environment. It should explicitly select the fixed collection and vector, disable SDK/model inference and app imports, and carry a full-body monotonic deadline. All public output is row-aligned NDJSON with an authenticated header and terminal receipt; physical EOF, statusOK, exactly 87 completed requests, every expected ID accounted once, and header/input hashes are required. Independently observed collection metadata cannot guarantee a transactionally frozen vector snapshot.

Each returned point must belong to its requested batch, have an exact numeric point ID and an object containing only the requested named sparse vector. Indices are unique, increasing uint32 integers; values are equally sized finite positive float32-representable numbers≤1. A present empty indices/values vector is a valid empty document, whose lexical dot is zero. A missing point, omitted vector, null field, malformed vector, duplicate/unexpected point or truncated response is explicitly classified; missing/invalid rows never become valid zero documents. Keep a mandatory validity/presence bitmap. Retain unrecognized term IDs and counts separately; terms absent from the pinned statistics have no pinned query-side IDF mapping and cannot be assigned invented IDs. No requests may reserve/create vocabulary terms.

## Usefulness and scope limits

These document vectors plus the existing index's term→ID/df/N table and deployed queryTerms/IDF functions are sufficient to compute local BM25F dots for the existing 101 English nonreference study, including per-unit BM25F and query BM25F. This supplies the missing lexical half of the existing coverage formula and enables a controlled study that preserves the production .12 BM25 weight and .3 coverage weight, original gates and candidate-score formulas. It does not independently recover production candidate unions, all omitted dense/facet/unit signals, reference profiles, title blends or grades. A followup scorer needs its own source and fixture review.

Current document vectors may have changed after the pinned index was built. Stable vocabulary allocation preserves existing term IDs; it does not prove that each point still has the historical text/body weights. The retrieval API provides no per-vector publication/build hash in the requested response. Fixed point IDs and equal collection metadata before/after therefore prove the addressed population and observed configuration only. The pinned 42934 population also excludes other collection titles; top300 computed over these rows is cohort-restricted, not a faithful live allTitles/lesserKnown candidate-pool reconstruction. Missing vectors and unknown terms are evidence of incomplete/mixed-snapshot coverage, not zeros or ranking parity.

This step is preparation-only, with no host operations, normal search, history/JeV calls, model calls, app changes or production writes. Existing task authorization covers public read-only investigation; no new owner approval claim is made.
