# Current catalog fingerprint retrieval for offline public-query ablation

Prepared only. No SQL request, host operation, model call, catalog/index publication, search or history write has been performed for this step.

The catalog source exists: `movie.fingerprint_scores` and `show.fingerprint_scores` hold the DNA scores copied by `dna_data.py`. `dna_updated_at` is a declared timestamp populated from the DNA record's `updated_at`. The existing title-snapshot publisher reads the 74 typed `fingerprint_scores['key']` subcolumns, and explicitly avoids reading the slower full dynamic object. This proposal reuses that read shape without invoking the publisher or importing application modules.

The exact ordered keys in Python `CoreScores` equal the 74 `VALID_FINGERPRINT_KEYS` in the webapp. Equality was checked from AST/type-source data, not by importing runtime services. The vector publisher validates the score dictionary with `CoreScores` and writes its ordered values to both `fingerprint_v1` and `fingerprint_v1_raw`; its Qdrant schema uses cosine for `fingerprint_v1`. A catalog extraction can therefore construct corresponding raw and L2-normalized vectors, but cannot prove that the current catalog equals the indexed Qdrant vectors or a past index-build snapshot. `CoreScores` declares integer fields without a source range validator; the proposed offline validity policy explicitly refuses nonintegral or out-of-range values instead of silently rounding/clamping them as the unrelated title-snapshot display format does.

The pinned current index build `20261012T041504Z` contains exactly 42,934 point IDs: 34,166 movies and 8,768 shows. Source point-ID mapping is `1_000_000_000_000 + tmdb_id` for movies and `2_000_000_000_000 + tmdb_id` for shows. The plan binds the verified compressed title-table SHA, index manifest SHA, exact point-ID order and independently derived `(media_type, tmdb_id)` mapping. No name matching or catalog-wide discovery is permitted.

Exactly two SQL statement strings are allowed, differing only in fixed table name `movie` or `show`. They select `tmdb_id`, each of the 74 fixed score subcolumns in bound key order, `dna_updated_at`, `adult` and `goodwatch_overall_score_voting_count`; the only argument is the fixed list of at most 500 approved TMDB IDs. The predicate is `tmdb_id = ANY(?)`, with `ORDER BY tmdb_id LIMIT 500`. No SQL string or column/table name is supplied by a caller. The complete fixed batches are in `retrieval-plan.json`: 87 sequential calls, below the 120-call cap. No retries, additional rows, table scans, independent count query, generic SQL seam, redirects or fallback endpoint are proposed.

An eventual minimal reader should use only stdlib HTTP/JSON/hash/matrix serialization, target one separately root-reviewed fixed Crate endpoint with POST `/_sql`, and receive credentials through private structured stdin or an existing root-owned secure source. Credentials and authorization headers stay in RAM and never enter argv, public outputs or diagnostic exceptions. Fixed statement/args equality is checked immediately before every request. Each response is bounded to 1 MiB; all responses together to 64 MiB; at most 42,934 returned rows; total wall deadline 300 seconds; each request at most the lesser of 10 seconds and global remaining time. An error, timeout, malformed JSON/column schema, nonfinite value, extra row/ID, duplicate ID, wrong table mapping or exhausted bound is terminal. Only typed/fixed error reasons and numeric progress are public; no raw error bodies, connection addresses or credential values are retained.

A successful HTTP response does not imply complete catalog coverage. Missing requested rows are retained as missing. Rows with null scores, missing/invalid score components, noninteger values, values outside 0..10, or zero total norm are retained as explicit fingerprint omissions. A valid zero component is a real score; an all-zero vector cannot be normalized and is omitted. No missing component is filled with zero, no clipping/rounding is applied, and invalid rows never participate in dot products. The actual public projected values and metadata may be stored locally; whole catalog objects and unrelated tables may not be read.

Output should include the original approved point order, current response presence/validity per row, the exact nullable projected 74 values, current `dna_updated_at`, current adult/vote metadata, per-batch acquisition bounds/times/digests, and aggregate omission reasons. Raw and normalized Float32 matrices can be aligned to all 42,934 rows with invalid rows filled with NaN plus a mandatory validity bitmap, so they cannot masquerade as valid zero vectors. Each matrix is 12,708,464 bytes. Consumers must intersect the validity bitmap before scoring and explicitly report dropped rows. A missing or malformed bitmap refuses evaluation.

Current adult/vote drift is reported independently against pinned index facts. The source index assumes at least 2,000 votes and excludes catalog adult=true; retrieval must not hide drift by adding those predicates to SQL. A follow-up evaluator must state its current-vs-pinned eligibility policy and compare all variants on the same explicitly valid/common candidate universe, rather than crediting fingerprint variants for silently dropping titles. Unknown adult/vote metadata remains unknown. No global consistency or no-change claim follows from one bounded pass: DNA timestamps and row content digests record observed version context, not a transaction across all batches or proof of unchanged Qdrant publication.

Meaningful local fixtures required before a concrete reader execution review: exact approved SQL/argument batches and count; same numeric TMDB ID in movie/show maps to distinct point IDs; shuffled responses restore exact index order; absent/null/partial/out-of-range/bool/nonfinite/all-zero scores cannot become valid; duplicate/unrequested/oversize/extra-column responses refuse; time/byte/call boundaries refuse without retry; credentials never appear in serialized public evidence; current adult/vote drift stays explicit; all compared scoring variants share the same validity intersection. Existing source score order must be matched rather than hardcoded from memory.

The resulting evidence could support a new **current-catalog fingerprint + pinned-index dense signal ablation** over the authored public corpus and existing grades. It is not faithful production ranking, historical fingerprint parity, current Qdrant vector attestation, organic traffic coverage or an acceptance result. No new index design or publication is included.
