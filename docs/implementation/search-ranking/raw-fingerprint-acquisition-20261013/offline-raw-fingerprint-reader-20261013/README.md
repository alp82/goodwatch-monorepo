# Standalone current-catalog fingerprint reader

Prepared and tested locally only. No production request or host operation has been performed. The original plan's `executionApproved: false` records its preparation state and is not a user permission requirement. Root may authorize a separately recorded read-only execution after reviewing these exact source bytes; no production write is included.

`reader.mjs` is a standalone Node ES module with stdlib imports only. It accepts the exact public 5,087,410-byte plan through stdin (maximum 8 MiB) and authenticates its SHA-256 before any endpoint or SQL operation. It then validates all 42,934 point mappings and the 87 fixed batches. The only queries are the two fixed SELECT strings and their bound ID arguments; no generic SQL input, retry, redirect, endpoint fallback or application-module import exists.

The first comma-separated `CRATE_HOSTS` value alone defines the endpoint, with `CRATE_PORT` when no explicit port is present. Only an HTTP origin with a numeric/DNS hostname and no userinfo/path/query/fragment is accepted; requests target exactly `/_sql`. `CRATE_USER` and `CRATE_PASS` are read from the existing process environment, used only in the HTTP authorization header, and never emitted. Root's eventual container invocation must choose and verify an existing exact container and authenticate the source before execution. The template contains placeholders and performs nothing.

All requests are sequential. Each has an absolute timer covering request and complete response-body reading, at most 10 seconds or the global remaining time. Response buffers are limited to 1 MiB per call and 64 MiB total; total execution is limited to 300 seconds from `runPlan` entry, checked before/after requests, after public row emission, and before completion. Public row emission also races the remaining deadline. No extra SQL follows a refusal. Stdin acquisition precedes `runPlan`; the root transport must separately bound that fixed public input transfer and the full process lifetime. Final failure-receipt emission is outside the acquisition's passing deadline and must be bounded by the root transport; an absent/truncated terminal receipt is incomplete, never success.

Output is public NDJSON: one header, each returned or missing requested title aligned by exact `indexRow` and point ID, and a terminal receipt. A successful acquisition has `complete: true` and `status: complete-acquisition-with-explicit-omissions`; this is not complete valid-fingerprint coverage or parity. Every row exposes a mandatory `validFingerprint` flag. Null/boolean/noninteger/out-of-range/all-zero vectors are explicitly omitted; nonnumeric malformed components are serialized as null, never arbitrary strings/objects or valid zero. Valid zero components are retained. Extra/duplicate/unrequested IDs, wrong column order, malformed metadata/JSON, rowcount errors and HTTP/transport/byte/deadline failures produce `complete: false` with fixed reasons. Current adult/vote metadata and DNA timestamps remain separate drift observations.

A downstream offline matrix builder must authenticate the exact plan and source, parse the entire NDJSON with exact EOF and terminal receipt, enforce one frame for every approved index row, and retain a mandatory validity bitmap before computing norms or cosines. Invalid vectors must not be filled with valid zeros. The initial reader emits raw projected values, not normalized matrices. A root execution artifact must independently record actual Docker/Node/SSH exit status and output hashes; the reader does not infer those lifecycle facts.

`test-reader.mjs` uses a locally owned loopback HTTP server and dummy credentials only. It verifies the entire 87-query/42,934-row plan, shuffled alignment, missing and invalid score accounting, credential absence, endpoint/no-fallback and terminal refusals. Tests use an injected clock only at a local test seam; CLI `main()` has no clock or limit override. They do not attest the actual Crate schema, existing container, credentials, runtime load, or Qdrant vector equivalence.

The source context compare records the original preparation working-tree files and the repository's `7aba` source. Public movie/show projection and fingerprint key mapping are unchanged; only unrelated schema-source text differs. Current catalog raw scores can support a common-valid-universe fingerprint+dense ablation, but are not a historical index-build fingerprint snapshot or proof of Qdrant equality.
