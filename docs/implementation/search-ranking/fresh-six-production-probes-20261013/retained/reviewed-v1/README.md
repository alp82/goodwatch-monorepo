# Fresh six-production-probe preparation

Prepared only. The previously approved 18 probes are consumed. This procedure requires fresh owner approval after rollout; no production commands have been executed by this preparation. The actual rollout commit and logging readiness must be independently recorded before an approval record is supplied. Root reviews the source/cohort before requesting approval. The default `node run.mjs` prints preparation metadata without fetching anything.

The six categories match the sanitized baseline: exact title, native title, low-vote title, person, description, reference. Original query texts were intentionally omitted from the public timing records, so this is an explicitly new public cohort, not an exact reproduction of the old six. Four texts derive from the 168-public-capture corpus. The Japanese native title is a new exact public title of Spirited Away. The Tomb (2007) is a new low-vote anchor supported by the existing public catalog acquisition: row 14186, point1000000042939, current votes1249; this is a point-in-time observation, not a guarantee of current metadata or result rank. Its lesserKnown flag is true. The other flags are identical and explicit across all six; filters are empty.

Each case issues one POST to the deployed public combined-search route. It reads provisional, reading, final and error frames from that same original request; it never repeats a query to obtain completion. Requests are strictly serial with no retries. A failed/timeout/refused case terminates the cohort instead of starting the next one. There is a 30-second full-response safety bound per request around the app's existing 15-second late-ranking window; the client does not change that window, ranking, paid-call policy, or app timeouts. Root must also supervise the whole process with a 210-second outer bound. A fresh absent output directory and O_EXCL intent consume the invocation before the first request.

The public HTTPS endpoint intentionally measures ingress/client stream arrival, unlike the historical controlled loopback baseline. A usable frame means a nonempty title or people batch, never a reading or empty provisional frame. First usable and full completion arrival, HTTP outcome, every batch's warning strings/counts, pending flags, server elapsed value, and chargedNano are retained separately. Full stream EOF is required. These are client observations, not browser render timing, independent rank correctness, organic p95, or automatic production acceptance. Refusal does not retry or erase partial evidence.

Normal app requests can use its ready interpretation cache or incur an ordinary paid interpretation and queue an ordinary history write. Fresh owner approval must cover that normal behavior; this preparation makes no cache-hit or zero-spend promise. The client cannot prove history persistence. Root must retain the existing allowlisted collector lifecycle/history-write events for the bounded invocation window and distinguish temporally associated events from exact request identity. Do not retrieve private history/query tables or claim six durable history rows from six HTTP200s. Zero fallback/error acceptance and both client first-usable/completion outcomes remain separate; a warning is recorded, never suppressed to manufacture PASS.

After rollout and fresh owner approval, root may provide a public approval JSON with schema `owner-approved-fresh-six-production-probes.v1`, exact planSha256, requests6, rolloutVerified:true, ownerApprovalRecorded:true, and the independently verified 40-hex deployedCommit. Only then is the reviewed command shape:

```
node run.mjs --execute-reviewed APPROVAL.json ABSENT_LOCAL_OUTPUT_DIRECTORY
```

This is a preparation recipe, not permission to run it. Approval booleans are recorded provenance supplied by root, not an independent infrastructure attestation. No role restart, backup, resource mutation, pinning, index publication, model prewarming, parallel request, or fallback retry belongs to this step.

Four local fixture groups use in-memory Response streams and an injected fetch function; they exercise first usable vs empty/reading, people-only delivery, same-request final/warnings/charge accounting, duplicate completion, truncation and HTTP refusal with exactly one fetch. No actual network is used by fixtures.
