## Remaining lesser issues (no unresolved P1 blocker)

- **P3: Authorize cheap command predicates before expensive adapters.** `goodwatch-webapp/app/server/yepwatch/service.server.ts:108` starts candidate discovery before machine host/phase/version/readiness checks. Three identical forbidden nonhost `start_round` attempts caused three candidate scans in the independent test. Move/reuse preflight authorization and fences before adapter work; assert zero catalog calls for forbidden/wrong-phase/stale commands. This is avoidable resource use, not a claim that unfinished production rate limits are a surprise security vulnerability.
- **P3: Expiry presentation still relies on a phase the API does not emit.** `yepwatch-app/src/app/room/[id].tsx:23`, `src/core/realtime.ts:78`, and server `machine.ts:5`: room UI disables actions from shared `phase==='expired'`, while service expiry returns 410 and socket error sets connection status only. Cached voting/setup controls can remain displayed/enabled after expiry; server access still fails closed. Source-based inference, not a six-hour browser reproduction. Test a socket expiry plus stale cached snapshot and show a terminal recovery view.

No significant unnecessary architectural complexity was found that warrants replacing the foundation. Thin catalog/evidence delegates are appropriate. The concrete needless work identified above is adapter execution before command preflight.

## Nonfindings and limits

- Shared snapshots explicitly whitelist participant, nested candidate/episode and offer fields. No raw votes, own state, progress history, individual consent, current-card trail or credential fields were found in shared payloads, apart from the corrected progress-query oracle outside the shared stream. Gateway schemas are strict, including the new public proposal field. Shared deck/proposals/shortlist/consent counts can imply preferences in small rooms; that disclosed inference is distinct from direct private fields.
- Full-round completion gates shortlist publication; roster stays frozen and late arrivals wait. Host/proposal-version checks and aggregate CAS protect final consent. Independent race: guest withdraws while host final availability recheck is held; stale CAS loses and retried decide rejects, with no decision committed.
- Exact-envelope lost-ack replay, payload/sequence mismatch rejection and vote-revision fences pass. Tickets are room-bound, short-lived and consumed by CAS; scoped leases recheck participant epoch and expiry. Cookie writes require allowed Origin; browser cookie/native bearer delivery and gateway service credentials remain distinct. No client DB/cache access or gateway catalog/storage authority was found.
- Subscribe-before-read, monotonic revision checks, bus-outage epoch fencing, lease deadlines and active-room audits are implemented. The reviewer reran their isolated gateway tests and inspected these paths. Durable Crate/Valkey multi-instance behavior is **not newly proven by those fixture tests**.
- Known remaining integration is separate: optional real GoodWatch member auth/prefill, real catalog/offer coverage, Crate durability/failover/restore, expiry private-payload cleanup/tombstones and delayed-write fencing, deployment/proxy/TLS, native secure storage and installed devices/accessibility/links. Room storage has expiry access checks but no private-payload cleanup worker in this foundation. None of these known incomplete boundaries is labelled a newly discovered production breach.
