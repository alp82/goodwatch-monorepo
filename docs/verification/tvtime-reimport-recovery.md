# TV Time full reimport recovery

October 24, 2026, #629. The owner requested recovery through a normal full archive reimport, with no extra match acceptance or file editing. This supersedes the earlier manual-only movie rule and year-only exclusion in the historical implementation notes. Existing explicit member choices remain authoritative. Confirm still writes the library; the client follows a completed replacement automatically unless the member has unsaved choices.

## Matching and ratings

- Movies are grouped by native UUID, never title. Automatic matches need one qualifying typed catalog movie after complete bounded TMDB search and candidate verification. The existing exact title/calendar-date rule remains. A new proof, `tvtime_exact_title_release_year_v1`, permits an exact primary/original title and the same primary release year. Alternative/translated titles still require the original exact calendar-date evidence. Typographic apostrophes/quotes normalize to their straight equivalents; no fuzzy titles or accent folding. Conflicting source titles, dates, countries, incomplete searches and multiple qualifying candidates remain held. A same-day candidate does not override a competing same-title/year candidate.
- Missing TVDB episode links can recover from TheTVDB's public episode page through its IMDb identity and TMDB's IMDb lookup. With a verified parent, no contradictory IMDb result, and one exact title/original-air-date match, metadata can recover an episode without a TMDB IMDb link. Presentation punctuation and a catalog-added `Episode N -` label are ignored, while title words and their order remain required. Season/episode coordinates alone never establish a match.
- A retired show ID requires an episode's independent identity and one exact, unambiguous catalog parent title. Resolved rows carry canonical TMDB episode IDs and retain source evidence. This recovery path never replaces current catalog TVDB IDs. Missing, challenged or malformed provider pages remain unresolved. HTML has a 1 MiB bound and shares job concurrency, request timeout, cancellation and attempt budgets. Recovery aliases are job-scoped and removed on completion, cancellation and discard. Reads are memoized by distinct show per page.
- Official `ratings-live-votes.csv`, `ratings-3-prod-episode_votes.csv`, `ratings-prod-episode_votes.csv` and `ratings-v2-prod-votes.csv` use the known `stars_wording_scalev2` labels: IDs `1,27,28,29,3` map to scores `2,4,6,8,10`. Keys split at the final hyphen, preserving movie UUIDs. Episode votes join watch evidence by episode ID; movie votes join tracking evidence by native UUID. Unknown IDs and emotions never become scores. Conflicting values for one canonical target are held rather than selected by file order. Liberator episode scores use the verified doubled-star scale; unverified extension scales stay held.

The rating labels are independently recorded in [Trakt's parser](https://github.com/trakt/trakt-web/blob/main/projects/client/src/lib/sections/settings/import/parsers/TvTimeGdprParser.ts) and [another importer's implementation](https://github.com/Avromiep/mytvwatchtime/blob/main/apps/api/src/import/lib/ratings.ts). The retired upstream endpoint was `msapi.tvtime.com/live/v1/ratings/sets`. Only the label facts were used; fixtures are synthetic.

## Reimport and validation

Watch source keys, dates, precision, passes and TVDB identities are unchanged for all **6,917 watches** in the real archive when comparing the old and new parsers. The watch writer derives idempotent IDs from these source keys. Additive intentions, protected states, conflict handling and score journals remain in use.

The end-to-end regression applies an earlier partial import, reimports the full archive with recovered watches and ratings, imports it again, changes member scores, imports again, and undoes the recovery import. It checks no duplicate watches or wishes, protected On hold state, preservation of newer scores, canonical episode placement, and removal only of additions owned by the undone import. Separate tests cover ambiguity, conflicting vote generations, legacy suggestion acceptance, provider failures, generation fencing, alias cleanup, and bounded transport.

`goodwatch-webapp/scripts/probe-tvtime-recovery.ts <private archive> <private cache directory>` uses live catalog SELECTs and an in-memory import/member database. All account, journal, alias and catalog-cache writes are intercepted. Real archives and response caches stay outside Git. A cold probe made 5,027 provider requests in 598 seconds; warmed runs reuse that provider evidence. Provider challenges are not identity evidence. Remaining unmatched records are reported rather than guessed.

The final reference replay matched **7,824 of 8,937 observations (87.5%)**, compared with 5,866 matched observations before recovery and before reading 849 episode votes. It held 95 parent-identity rows, 745 episode-identity rows, 271 movie-identity rows and two nameless movie rows. No unsupported or invalid rows remained in this particular export. The replay did not Confirm on a real account. Live results can vary with provider availability; the fallback remains conservative when TheTVDB returns a challenge page.

Validation: all **631 import and import-UI tests** passed; production build passed; TypeScript reported the same **189 existing errors** as an isolated main checkout, with no added diagnostics. Independent Standards and Spec reviews identified alias cleanup, repeated database reads, conflicting score generations and documentation drift; each was corrected and the relevant tests rerun.
