## Result and semantics

- A member's home leads with **Watch next** and the existing first Next pick, with its cinematic backdrop, large title, actual runtime, available service, and taste match where known. An episode uses its actual runtime; a show to start labels the usual runtime as minutes per episode. No progress is invented.
- The initial action opens that title's details. My movies opens the existing page; My shows opens its existing TV screen. More picks retains the existing Watch next screen, including its existing discovery fallback. Discover, Taste, Search, and the remote's provider keys remain reachable. No action added here marks a title watched, rates it, or changes Wishlist membership.
- Popular titles form a secondary horizontal row. Their source is the existing living-room `poolCandidates` catalog and popularity order. The member's `hidden`, `seen`, `skipped`, and `wishlist` exclusions are applied per request, matching the pool. Hidden includes Not interested and Dropped. Saved-service matches in the authenticated viewer's country come first; fewer than twelve matching titles are filled with eligible titles from the wider catalog. The row labels service-only, mixed, wider-catalog, and unknown-availability results honestly. Taste match can be displayed but never changes this row's popularity ordering.
- Popular is a member-only loader read using the existing authenticated `ViewerContext`, title snapshot, availability index, and title-card reader. There is no new API route, shared personal cache, or account-id input. The shared **Start titles** below the room are unchanged. The glossary distinguishes the two lists.
- Removed the home taste-guide rendering and `loadHomeSides` loader call. Taste remains a separate screen; its data loads there. The home no longer presents taste-group entries, heroes, or guide actions.
- Removed Explorer from the shared TV app list and its home prefetch. Existing `tv=explorer`/island bookmarks still open the compatible TV screen. No standalone Explorer page/domain was deleted. The remote and menu do not offer Explorer.
- Guests keep their existing app/service tile home, minus the intentional Explorer navigation removal. Existing Watch next selection, Recently landed promotion, tracking, and saved-state rules are unchanged.

## Layout and return behavior

Member actions and popular posters have separate horizontal rows using pass-1 scrolling and history restoration. The main title region is reserved, so short and long names do not move the popular row. Short phones use a compact single-line main title and minimum-width popular thumbnails; the full title remains available in details and each poster's accessible label. Popular touch targets were checked at least 44 × 44 CSS pixels at 390×844, 360×740, and 375×667. The shared `TitleList` is unchanged.

Browser checks open the primary title, open/close Fingerprint, and return to the invoking home action. They also move along Popular, enter details, and assert the same selected poster and exact row offset on Back. Both editions render the machine's item order; only the CSS-visible edition is interactive in the existing room architecture. Completed independent authenticated SSR and behavior checks are recorded separately below; clean hydration remains false on both baseline and current snapshots.
