Emergency residential proxy for the TMDB watch crawl

Research date 2026-10-17. Read-only: nothing was signed up for. Prices are list prices without VAT, read from official pages. Marked UNVERIFIED where only a third party or a half-rendered page said so.

First choice: DataImpulse, Intro $5

$5 → 5 GB, $1/GB

Fits the $5 up front exactly. Traffic never expires, there's no subscription, and country targeting is free. It came 5th of 10 in Proxyway's 2026 benchmark with a 99.74% success rate. The dashboard can cap traffic over a rolling 24 h window and suspend when the cap is hit, which gives a hard backstop behind our own cap.

Backup: Geonode, pay as you go 10 GB

$8.80 → 10 GB, $0.88/GB

Purchased bandwidth doesn't expire and the page promises no multipliers. Its Trustpilot score is 4.5. It's the cheapest per GB of the providers checked, but the first buy is $3.80 over the $5 budget, and no independent benchmark covers it.

What $0.30 a day buys

≈ 0.3 GB ≈ 6,000 pages

I measured 41.6 KB per page gzipped; uncompressed it's 195 KB, so Accept-Encoding: gzip matters. Response headers add ~2.3 KB. A new TLS tunnel adds ~6–8 KB more (UNVERIFIED estimate). Count about 50 KB per page with fresh connections and ~44 KB with keep-alive.

Recommendation

Why DataImpulse first

  • Price and credit: It's the only provider at about $1/GB whose first purchase fits $5. "Unused GBs never expire" means a quiet month wastes nothing (pricing).
  • Reliability: Proxyway 2026 measured 99.74% success and 0.97 s average response on the global pool. Its Premium pool reached 99.82%. Only Oxylabs, Decodo and SOAX scored higher, and they cost 3–6× more (Proxyway).
  • Stability of the setup: One gateway, gw.dataimpulse.com, port 823 for HTTP(S) rotating and 824 for SOCKS5. Settings go in the login after __ (protocols, parameters). Sticky sessions last up to 120 min.
  • Hard cap at the provider: A traffic limit over 1 h, 24 h, 7 d or 30 d windows can email you, suspend the account, or both. Requests then get USER_RATE_LIMIT_EXCEEDED (traffic limit).
  • Sourcing: It says it's first-party, with people opting in through a disclosed SDK in partner apps in exchange for perks (its own claim). No KYC is needed for ordinary sites; TMDB isn't on its blocked list. Refunds are available for 7 days.

Weak points to accept

  • Reputation: Trustpilot withholds its score for "breach of guidelines" (fake reviews removed). IPRoyal and Evomi carry the same flag. Complaints mention more GB used than expected and a frozen account after a security incident.
  • IP quality: In Proxyway's test, 49.6% of its IPs were flagged as residential proxies by IPinfo; Webshare was at 33.6% and IPRoyal at 16.7%. That matters only if TMDB's AWS WAF uses reputation lists. Today the block looks per-IP.
  • Next purchase: The $5 Intro is one-time for new customers. The next tier is $50 for 50 GB, still $1/GB and never expiring. At the 0.3 GB/day cap, 5 GB covers ~16 blocked days and 50 GB covers ~166.

Why Geonode as backup

Geonode is the only other provider at about $1/GB with credit that doesn't expire and a small first buy. It's also the cleanest reputation in that price band: Trustpilot 4.5, with complaints about charges after the trial and slow speeds. Gateway proxy.geonode.io:9000 rotating, username user-country-DE-session-abc-lifetime-30, SOCKS5 supported (docs). A 3-day $5 trial exists, but trials tend to roll into charges, so buy pay-as-you-go directly. Downside: no independent benchmark, and its API reports usage, not balance.

If both get blocked at TMDB, the quality fallback is IPRoyal: lowest flagged-IP share, a balance API (GET https://resi-api.iproyal.com/v1/me), per-sub-user daily limits and credit that never expires. At $7.35/GB, though, $0.30/day buys only ~40 MB, about 800 pages.

Exact purchase

  1. DataImpulse: Residential Proxies → Intro, $5 for 5 GB (one-time, new customers). It's not Premium Residential, which is priced separately. Don't buy city, ASN or ZIP targeting add-ons; those are "extra costs".
  2. In the dashboard: Traffic limit on the plan, 24 h window, 0.35 GB, action = suspend + email. That sits just above our code cap of 0.30 GB, so it only fires if our accounting is wrong.
  3. Backup, only if DataImpulse fails or bans: Geonode → Residential → Pay as you go, 10 GB, $8.80.

Wiring it in

Secret

Create a Windmill secret variable u/Alp/TMDB_PROXY_URL, following the u/Alp/REDIS_PASS convention, with the value:

http://LOGIN:PASSWORD@gw.dataimpulse.com:823

No country parameter is set, so the exit comes from the whole pool. The country comes from ?locale=XX in the URL, and validate_selected_country already checks it. If a test shows TMDB picks the country by IP instead, use LOGIN__cr.us. An empty value turns the proxy off. For Geonode, swap the value for http://USER:PASS@proxy.geonode.io:9000; nothing else changes.

Proxy only while we're blocked

Today crawl_tmdb_watch_page in goodwatch-flows/windmill/f/tmdb_web/tmdb_crawl_providers/fetch.py calls requests.get directly. The proposed flow:

  1. Direct by default: Go direct unless the Redis key tmdb:egress:direct_blocked exists.
  2. On a direct block: When a direct request comes back limited (403, 429 or "Request Error (403)"), set the key with a TTL of Retry-After, or 6 h if it's missing.
  3. While the key exists: Fetch through the proxy, provided TMDB_PROXY_URL is set and today's byte budget allows it.
  4. After the TTL: The next request goes direct again. If it's still blocked, the key is set again.

The 12 workers share this state through the existing f.db.redis.RedisConnector, the same pattern as f/dna/generate/spend_pause.py.

Per-day byte cap, enforced before each request

Each request first reserves a conservative 60 KB in a per-UTC-day counter and then corrects it to the measured bytes. The reservation is atomic, so 12 random workers can't overshoot together. When the budget is spent, the crawl reports rate_limit_reached with retry_at = next UTC midnight; the existing code already backs off on that.

"""TMDB egress: direct by default, residential proxy only while direct is blocked."""
from datetime import datetime, timedelta, timezone

import requests
import wmill

from f.db.redis import RedisConnector

BLOCKED_KEY = "tmdb:egress:direct_blocked"
DAILY_PROXY_BYTES = 300_000_000          # 0.30 GB ≈ $0.30 at $1/GB
RESERVE_BYTES = 60_000                   # body ~42 KB gz + headers + TLS/CONNECT
TUNNEL_OVERHEAD_BYTES = 8_000            # UNVERIFIED estimate, reconcile with dashboard
_session = requests.Session()            # keep-alive: reuses the tunnel and exit IP


class ProxyBudgetSpent(Exception):
    def __init__(self, retry_at):
        self.retry_at = retry_at


def _day_key(now):
    return f"tmdb:proxy:bytes:{now:%Y-%m-%d}"


def _next_midnight(now):
    return (now + timedelta(days=1)).replace(hour=0, minute=0, second=0, microsecond=0)


def fetch(url, headers, timeout):
    redis = RedisConnector().get_redis()
    proxy_url = (wmill.get_variable("u/Alp/TMDB_PROXY_URL") or "").strip()
    if not proxy_url or not redis.exists(BLOCKED_KEY):
        return _session.get(url, headers=headers, timeout=timeout), False

    now = datetime.now(timezone.utc)
    key = _day_key(now)
    total = redis.incrby(key, RESERVE_BYTES)
    redis.expire(key, 3 * 86400)
    if total > DAILY_PROXY_BYTES:
        redis.decrby(key, RESERVE_BYTES)
        raise ProxyBudgetSpent(_next_midnight(now))
    try:
        response = _session.get(
            url,
            headers={**headers, "Accept-Encoding": "gzip"},
            proxies={"http": proxy_url, "https": proxy_url},
            timeout=timeout,
        )
    except requests.RequestException:
        redis.decrby(key, RESERVE_BYTES - TUNNEL_OVERHEAD_BYTES)
        raise
    wire = response.raw.tell()            # compressed body bytes read off the socket
    head = sum(len(k) + len(v) + 4 for k, v in response.headers.items())
    redis.incrby(key, wire + head + TUNNEL_OVERHEAD_BYTES - RESERVE_BYTES)
    return response, True


def mark_direct_blocked(retry_after_seconds=None):
    ttl = int(retry_after_seconds or 6 * 3600)
    RedisConnector().get_redis().set(BLOCKED_KEY, "1", ex=max(60, ttl), nx=True)

Notes: response.raw.tell() is urllib3 2.x and counts compressed wire bytes after .text is read. requests handles only HTTP/1.1; that's fine here. In crawl_tmdb_watch_page, call fetch instead of requests.get. When via_proxy is false and the response is limited, call mark_direct_blocked(...). Map ProxyBudgetSpent to rate_limit_reached=True, retry_at=e.retry_at. A 403 through the proxy is still treated as limited, but it doesn't set the direct-blocked key.

Caveats

  • TMDB's terms: They forbid circumventing security features. Using rotating proxies to get around a block placed on our IP is exactly that, as the earlier egress research noted. Read the terms of use before buying, and keep request rates polite even through the proxy.
  • Untested on TMDB: No independent benchmark covers AWS CloudFront or AWS WAF targets, so the first $5 is the real test. Run ~200 pages through the proxy and record the share of 200 responses that pass validate_selected_country.
  • Billing accuracy: How each provider counts bytes, in both directions and with TLS overhead, is unpublished. Our counter is an estimate; the dashboard limit is the authority.
  • Free options first: The earlier egress research lists free options worth trying before paying: Hetzner IPv6 and a fixed TLS fingerprint.
