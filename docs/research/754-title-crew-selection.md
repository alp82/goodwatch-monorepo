# Title crew selection: issue #754

Investigated October 26, 2026, against main
`bb1265d4a5a980a4fcd32023fed85ac49029a7d0` and production, using only
HTTP GETs, Crate SELECTs, and Redis GET/TTL commands. No production cache
was cleared and no application server was started locally.

## Verdict

The reported render-to-render variation did **not** reproduce. Recommend
closing [#754](https://github.com/alp82/goodwatch-monorepo/issues/754) as
not reproducible on current main. This does not establish the cause of the
October 23 snapshots. No application change or speculative tie-breaker fix
is included.

## Production comparisons

Requested `https://goodwatch.app/movie/629-the-usual-suspects` sixteen times:
eight Chrome user-agent GETs and eight Googlebot user-agent GETs, without
cookies. Eight used the exact URL; eight added distinct `crew_probe_754`
query parameters to exercise separate document keys. These were HTTP
document comparisons, without executing browser JavaScript.

All responses were HTTP 200. Both their visible Crew blocks and their
serialized loader `crew` values were identical. Fifteen reported
`GW-Page-Cache: miss`, one reported `hit`; all reported
`GW-Cache-Identity: anon;US;en` and `Cache-Control: private, max-age=0`.

| Crew line | Names in every response, in order |
| --- | --- |
| Directed by | Bryan Singer, Haley McLane, James D. Deck |
| Written by | Christopher McQuarrie |
| Produced by | Bryan Singer, Francine Maisler, Lisa Miller Katz |
| Composed by | Charleen Richards-Steeves, Tami Treadwell, Chuck Michael |

Twelve direct executions of the crew selection (four per configured Crate
coordinator) returned one identical selection. Six further executions of
the **complete SQL statement generated by current `details.server.ts`**,
two per coordinator, also returned that selection. The complete statement
was captured with an injected query function, without importing production
services or invoking the cached/corrected details getter.

The direct SQL selection differs from the HTML: Alan Steinman replaces
Haley McLane, and John T. Cucci replaces Chuck Michael. A Redis GET of
the exact `details-movie-v2` key for `{country: "US", language: "en",
movieId: "629"}` returned the **same crew as every HTML response**.
Its timestamp was `1792932494825` (about 11.4 hours old at inspection),
with 45,358 seconds remaining TTL. The corresponding DE and GB keys were
absent. A cross-layer equality assertion therefore failed as
`DATABASE DIFFERS FROM PAGE`; the within-layer repeatability assertions
passed. This difference is not evidence of render-to-render randomness.

## Query and cache findings

- The visible crew query filters each role by job **or department**, then
  orders by `episode_count_total DESC NULLS LAST, popularity DESC NULLS LAST,
  credit_id ASC` before `LIMIT 3`. `Crew.tsx` renders those arrays directly.
- Title 629 currently has 128 joined crew rows, zero null credit IDs, and
  zero duplicate `(episode_count_total, popularity, credit_id)` sort keys.
  Null-credit ties do not explain this title with its current data.
- Current Directing popularity is Bryan Singer 1.9438, Alan Steinman
  0.5193, James D. Deck 0.48, Haley McLane 0.4756. Current Sound popularity
  starts Charleen Richards-Steeves 1.351, Tami Treadwell 1.2242,
  John T. Cucci 1.081, Leigh French 1.0764, Chuck Michael 0.9761.
  Direct SQL follows this order.
- `title-details-cache.ts` keys by title, country and language, with twelve
  hours fresh and twelve hours stale. An older cached selection can differ
  from today's popularity ranking. Redis explains the observed current
  HTML/SQL discrepancy; changing popularity is a plausible explanation for
  changes over time, not a proven explanation of the historical snapshots.
- Both crawler and browser movie loaders call `getDetailsForMovie`.
  The crawler's canonical option skips title translation, not crew selection.
  The OG renderer uses the same details getter, with US/en and canonical
  content. There is no separate OG crew-selection query.
- JSON-LD uses `media.credits`, a separate projection in the **same SQL
  statement**, filtered by exact job and ordered by popularity. This gives
  Bryan Singer as director and John Ottman as composer in the sampled HTML.
  It does not supply the visible Crew block. The job-or-department behavior
  explains why sound technicians appear under “Composed by”; changing that
  product behavior is outside this investigation.

The October 23 files `026.raw.html` and `027.raw.html` under
`~/.cache/gw753-html-check/prod-baseline/` still contain the differing names
reported in the issue. Both identify US/en; this is not simply a different
country in those captures. They do not include the contemporaneous source
popularity values or Redis entry timestamps, so this investigation cannot
distinguish a cache/deployment transition from another historical cause.
