# Selected-language media metadata: inventory and first technical plan

Research date: 2026-10-12. Source checkout: `4e37885ae9d2ec2ba3d58f0ef63e7b53d3d4084e`, branch `fix/search-provisional-title-results-406`. This is a preliminary plan, not an implementation spec or accepted UX decision.

## Scope and evidence boundaries

Requested outcome: country and language controls can move together and can be independently selected; movies and shows display their selected-language titles, posters and descriptions across all relevant surfaces. Taglines belong in the same metadata boundary. Coupling interaction is **undecided**: the latest user suggestion is to ask whether to change the companion value, with a preview. Neither persistent “Match country” mode nor a binary linked-state storage model is approved. Posters, descriptions, guest access and coupling are part of the plan; text-only, uncoupled or Latin-only releases are optional sequencing proposals, not scope decisions.

This research used local source, official TMDB and W3C documents, and read-only GitHub issue bodies/comments. No application changes, commits, issue mutations, infrastructure changes, API credentials, live metadata calls or production aggregate scans were made. An isolated synthetic execution of the existing TMDB conversion functions and local font-character inspection provided narrow additional checks. Source code verifies what this checkout does, not which flags or pipeline versions are deployed.

UX inputs were read via `ghostex read-session-chat`: Fable `S0c:P4wz7:G427l` (substantive inventory 22:16 and staged-preview follow-up 22:19), Opus `S0c:P4wz7:G5ugv` (corrected scope 22:15 and preview review 22:19), local times Europe/Berlin. They are design evidence and proposals, not user decisions. Opus's earlier movie-only production counts are reported evidence only: approximately 1.136 million English translation rows, 143,709 German rows (61,426 nonempty titles, 112,520 descriptions), and 176,993 French rows. These counts were not reproduced, do not measure presentable-title coverage, and do not imply blank titles lack usable local names. Its examples of Chinese and Portuguese regional differences motivate explicit variant handling, not a BR-before-PT policy.

Labels used below: **verified repo** means source-backed behavior; **upstream documented** means a current official contract; **reported** means another research thread's observations; **proposal** means an implementation recommendation; **unknown/decision** means a gap requiring evidence or product input.

## Main findings

1. **Verified repo:** localization data already has a home. Crate's `translation` rows contain language + country, title, overview and tagline; `media_image` contains language-tagged posters and other artwork. The current webapp never reads `translation`; its only `media_image` query reads backdrops. This is primarily a serving/preference/cache project, with coverage verification and possible targeted backfill, rather than a need for a new title catalog. [Schemas](../../goodwatch-flows/windmill/f/sync/models/crate_schemas.py), [details query](../../goodwatch-webapp/app/server/details.server.ts).
2. **Verified repo:** details accept and cache language, but the SQL argument is `_language` and is unused. Movie/show routes default to `en`; Discover's older parameter builder uses request locale. Regional inputs such as `pt-BR` are normalized to `en` by the details cache's two-letter validator. [Details query](../../goodwatch-webapp/app/server/details.server.ts), [cache normalization](../../goodwatch-webapp/app/server/title-details-cache.ts), [movie loader](../../goodwatch-webapp/app/routes/movie.$movieKey.tsx), [show loader](../../goodwatch-webapp/app/routes/show.$showKey.tsx), [Discover parameters](../../goodwatch-webapp/app/utils/discover.ts).
3. **Verified repo:** the shared title-card reader caches canonical display fields only by title key; several surfaces bypass that reader altogether. Changing a poster component or the details SQL alone cannot produce consistency. [Cards](../../goodwatch-webapp/app/server/title-cards.server.ts), [library](../../goodwatch-webapp/app/server/my-library.server.ts), [person credits](../../goodwatch-webapp/app/server/person.server.ts), [share titles](../../goodwatch-webapp/app/server/share-lists/titles.server.ts).
4. **Verified repo:** request cache identity already separates country and language; explicit preferences must be integrated before cache lookup and SSR. Current language comes from a valid anonymous `GW-Cache-Identity` header, otherwise `Accept-Language`, otherwise `en`. It does not come from saved settings or localStorage. [Identity](../../goodwatch-webapp/app/server/cache-identity.server.ts), [page cache](../../goodwatch-webapp/app/server/page-cache.server.ts).
5. **Verified repo:** query language and display language are different concerns. Query routing/translation works from typed text, while title lookup requests TMDB `en-US`; local ranker name indexes contain canonical and original titles, not translation aliases. Display localization should be applied after retrieval/ranking. Localized-name findability needs its own alias work and evaluation. [Search pipeline](../../goodwatch-webapp/app/server/combined-search/search.server.ts), [language routing](../../goodwatch-webapp/app/server/combined-search/language.server.ts), [index construction](../../goodwatch-webapp/app/server/search-ranking/search-index-build.server.ts).
6. **Verified repo:** My library is the important order exception: Title sort and its local text filter read names before pagination. The current sort strips English articles and uses English collation. Localizing only the visible page would make its sorting/search wrong. [Library domain](../../goodwatch-webapp/app/domain/my-library.ts), [library name cache](../../goodwatch-webapp/app/server/my-library.server.ts).

## Official upstream behavior and limits

| Question | Upstream documented behavior | Consequence / uncertainty |
| --- | --- | --- |
| Language versus availability country | TMDB metadata language uses ISO 639-1, usually with an ISO 3166-1 suffix such as `en-US`. Its `region` parameter controls release-date presentation/filtering; watch-provider availability is grouped by country. [Languages](https://developer.themoviedb.org/docs/languages), [regions](https://developer.themoviedb.org/docs/region-support), [watch providers](https://developer.themoviedb.org/reference/movie-watch-providers). | Keep availability country distinct from display locale and its translation region. `language=de-DE` does not select German streaming offers. No official country-to-preferred-language rule is supplied by these contracts. |
| Translation structure and partial values | Movie and TV translation endpoints list contributed translations. Official OpenAPI examples carry `iso_639_1`, `iso_3166_1`, `data.overview`, and movie `data.title` versus TV `data.name`; examples include empty fields. [Movie translations](https://developer.themoviedb.org/reference/movie-translations), [TV translations](https://developer.themoviedb.org/reference/tv-series-translations), [official OpenAPI](https://developer.themoviedb.org/openapi/tmdb-api.json). | A translation row is not proof all four fields exist. Inspect values independently and retain blank/missing distinction where possible. No coverage SLA or complete text-fallback contract was found in the current references. |
| Empty translated title | A historical TMDB moderator response describes blank duplicate English translated titles and links the contribution Bible. ## Shared localization boundary: proposed foundation

Define one pure locale resolver and one batched metadata resolver, shared by page and search roles:

```text
request + explicit view overrides + account/device preferences + defaults
    -> effective availability country + effective presentation locale + provenance

stable title IDs + effective presentation locale + fallback-policy version
    -> title, synopsis, tagline, poster (+ field source/actual locale/fallback reason)
```

This is a proposed contract, not code to implement in this research. Country-language association tables, supported locales, regional preferences and coupling interaction are external policy inputs. Resolve metadata locale separately from availability country: a stored explicit `pt-PT` must not silently become `pt-BR` because someone checks Brazilian offers unless product explicitly chooses that behavior. A language-only choice such as `pt` needs a documented regional resolution rule; concatenating language with any watching country (`pt-DE`) is not sufficient.

Use the existing normalized media type and stable title identity (including duplicate-title canonicalization); retain `canonicalTitle`, `originalTitle` and display fields separately. Batch base rows, translations and posters by title IDs; preserve input order and presentability decisions. Create new objects rather than mutating cached canonical rows. The same resolver must feed details, cards, direct SQL/Qdrant result adapters, preview and image renderers. A page of 40/60 cards should have bounded batch reads, not 40 upstream calls.

**Proposed conservative text handling, pending policy:** choose a deterministic candidate locale sequence; use nonempty fields independently. If the selected primary language equals the stored original language, original title is a defensible title fallback; do not extend this to “same script.” Otherwise use a nonempty approved regional translation, then canonical fallback (currently generally English/default upstream metadata), finally original only as a last nonblank identifier. An exact-region row with blank title is ambiguous: do not claim it is an untranslated title or silently label its canonical fallback as selected-language text. Retain a fallback reason. Product may choose original title for intentionally same-name rows if reliable upstream semantics/intent become available. Do not backfill blanks with English text in `translation`.

An original-first fallback for all missing titles, English-first fallback, and special treatment of existing blank rows are alternatives requiring product input. Description/tagline can fall back to canonical text or be omitted; there is no original synopsis column equivalent to `original_title`. Never fabricate translations. Posters can follow TMDB's documented language → original language → best available chain, or a chosen language → neutral/English/canonical chain. Rank within a language tier by an agreed quality/vote rule, then a stable path tie-break; avoid SQL row-order dependence. Neutral posters are not guaranteed suitable for every script/market. Poster fallback and text fallback need not select the same locale, so return field provenance.

### Preview and apply, independent of UX choice

Latest UX synthesis recommends a staged Country / Titles in panel: optional companion change, real metadata preview, Apply naming exact changes, Cancel/Escape/dismiss discarding the **entire** draft, and no remembered checkbox or hidden mode initially. This is a recommendation, not a user decision. Opus's “dismiss saves primary” proposal is incompatible with these staged semantics and is not recommended here. Country may suggest languages; language must not infer a country. Persistent follow-country is still an alternative; add mode storage only if accepted.

Technical requirements for either interaction:

- Preview prospective values with the real resolver, using the current title or a clearly identified sample. Show unchanged/fallback outcomes truthfully. Preview should expose title, poster and description/tagline availability; a hand-picked fully localized title cannot imply the whole library is translated.
- Read-only preview must not write preferences, transfer state, interactions or URL history; normal read-cache population is fine. Cancel pending previews or reject responses for an old draft. Keep current and prospective keys distinct.
- Country preview may show saved services supported in a country from the provider catalog, but that does **not** prove a title is offered there. Per-title offer previews must use country-specific availability evidence, freshness and paid/subscription selection through [watchability](../../goodwatch-webapp/app/routes/api.watchability.ts) and [availability index](../../goodwatch-webapp/app/server/availability-index.server.ts). Preserve “unknown availability” versus no offer.
- On Apply, validate the complete intended pair, persist once, then publish one effective context and invalidate affected payloads/loaders. **Verified:** the member settings API accepts multiple keys, but its [generic upsert](../../goodwatch-webapp/app/utils/crate.ts) executes each row separately in a loop. A later row can fail after an earlier row saved; this is not an atomic pair. Store the preference pair as one versioned record/value or add a proven all-or-nothing write boundary; keep legacy country reads compatible. Two localStorage `setItem` calls are not atomic. For guests, a single serialized device-preference envelope avoids a half-written pair; server-visible representation must carry the same version. Persisting one device envelope and a server-visible cookie still needs a defined failure/reconciliation rule; those are two stores, not a cross-store transaction.
- Failed Apply leaves the previous effective context usable and exposes save failure. A language-only apply leaves availability inputs unchanged; a country-only apply can affect text variants only if approved locale policy reads country. Apply-both must not trigger another companion prompt. Undo is optional UX work and must restore the pair through the same boundary.

### Guest SSR and account consistency

Preserve guest selection. A localStorage preference and post-hydration URL rewrite cannot guarantee selected-language first paint. Two viable foundations are (A) explicit view locale in all navigation/API URLs, with deliberate shared-link semantics, or (B) a server-readable guest preference cookie folded into effective request/cache identity. A cookie need not force `Vary: Cookie` on every analytics cookie: the existing identity abstraction can encode normalized relevant preference values. The cookie/header/URL precedence must be one rule in both `cacheIdentityOf` (before page-cache lookup) and loaders. A future front cache must implement the same derivation and overwrite client-supplied identity headers. Until it can, bypass shared caching of affected requests rather than miskey them.

Members resolve saved preferences on the server; current root locale does not. Decide whether URL locale is a temporary view override and whether shared links retain sender context or use recipient preferences. Neither Fable's language-bearing shares nor Opus's recipient-language shares is accepted. Account preference consistency across settings, onboarding, active title controls and transfer is required once an action is declared a saved preference. A temporary availability view should be represented separately, not persisted accidentally. Old localStorage country can be migrated into the envelope or reconciled by explicit transfer; do not let it overwrite an existing member preference on first paint.

## Search, ranking, library names and identity

**Verified repo:** [language routing](../../goodwatch-webapp/app/server/combined-search/language.server.ts) detects typed text with language markers, and optionally translates it to English using an existing versioned contract. This does not consult display preference. Native fallback uses multilingual vectors. [Title embedding inputs](../../goodwatch-flows/windmill/f/search/title_text.py), [embedding job](../../goodwatch-flows/windmill/f/search/embed_titles.py), [index builder](../../goodwatch-flows/windmill/f/search/index_builders.py), [ranker](../../goodwatch-webapp/app/server/search-ranking/rank-search.server.ts) use canonical/original names and English analysis/evidence, with named `text_en_v1`, `text_multi_v1`, `terms_bm25f_v1` vectors. “Multilingual model” does not imply every localized name is in that corpus.

**Proposal:** keep query interpretation, fingerprint/taste calculations and score/popularity/date/relevance ordering independent of presentation locale. Localize the response after those steps. Current title matching highlights may stop matching when display title differs; retain matched alias metadata rather than recomputing relevance from display text. Both provisional and final streams must use the same effective context. Existing search-detail revalidation compares URL country and language, which is useful, but preference-only changes also need loader revalidation.

For consistent title findability, add translation aliases to local exact/prefix/fuzzy lookup and “like X” reference resolution. Deduplicate by stable ID and resolve ambiguous names with existing evidence/votes, not the viewer's display language alone. Search all approved aliases independently of the presentation preference; preference may affect displayed label, not hide the canonical/original title. TMDB title search remains useful for titles absent locally, but localized fields for those rows need a bounded upstream/local strategy and an explicit fallback. Replacing `language=en-US` with the selected language can change recognition behavior: evaluate it rather than promise identical results. All aliases may require more index memory; measure before loading the whole translation corpus into every search role.

Display-only work needs no dense-vector re-embedding. An alias index build/version update may be sufficient. If translated evidence is added to vectors/BM25F, that is a new retrieval contract and requires coordinated Windmill/webapp rebuild and ranking evaluation, per [ADR 0002](../adr/0002-local-text-embeddings-for-search.md). Search is a separate role and may run a different commit; contract rollout must work across old/new page/search processes, per [ADR 0011](../adr/0011-search-runs-as-a-role-of-the-webapp-image.md).

For My library, the proposed Title sort follows resolved display names, with explicit locale collation and stable ID ties. Resolve names for all status keys before pagination; cache separately from visible card payloads. Its current in-library search matches only one canonical title. Proposed alias matching should search canonical, original and approved localized names regardless of display locale, so changing presentation does not make a searched item disappear. It can change Title-sort order and page boundaries; reset/reconcile pagination after Apply. English-only article stripping is current behavior, not an accepted language policy. Other sorts should retain existing order. [Domain](../../goodwatch-webapp/app/domain/my-library.ts), [server cache](../../goodwatch-webapp/app/server/my-library.server.ts).

## SSR, SEO, markup and fonts

**Verified repo:** `detailsPageMeta` builds a title-bearing canonical URL and English generated description. `buildMeta` builds JSON-LD from details, uses original media language for `inLanguage`, includes `google: notranslate`, and creates a path-only OG URL. Sitemap generation derives slugs from canonical title/original title. Numeric-ID route parsing means display localization does not require changing title identity/slugs. [Meta](../../goodwatch-webapp/app/utils/meta.ts), [details meta](../../goodwatch-webapp/app/utils/detailsMeta.ts), [sitemap](../../goodwatch-webapp/scripts/create_sitemaps.py).

**Proposal:** preserve stable canonical identity fields when overlaying display metadata; otherwise changing viewer language changes canonical/OG URLs accidentally through `details.title`. Whether to publish separate crawlable locale URLs, hreflang and localized sitemaps is a product/SEO decision. A query parameter alone does not establish a complete alternate-page policy. Metadata descriptions derived from fingerprints remain English until generated prose/UI translation is approved; do not promise localized descriptions in meta where the implementation still uses generated English summaries. Keep media `inLanguage` semantics separate from page-text language. Localize title mentions within English prose without pretending the whole sentence is translated.

Keep `<html lang="en">` while English is the primary interface/document language. Mark actual localized content, and fallback content, per element; use bidi isolation/direction for mixed scripts where needed. A German selected preference with an English fallback paragraph should mark that paragraph English. Changing the document language only because a poster/title is German would mislabel English navigation and controls. This follows [W3C language declaration guidance](https://www.w3.org/International/questions/qa-html-language-declarations), which assigns a document default and overrides it around other-language text. Document title/attribute values cannot always express mixed-language segments cleanly; validate assistive output rather than assume `lang` fixes every case.

Validate actual browser, canvas and exported images for selected scripts; add suitable fonts/shaping support where needed. Do not infer missing glyphs solely from filenames or restrict launch languages without product approval. ## Minimal phased implementation proposal

These are implementation phases, not accepted partial-release scopes. Requested titles, posters and descriptions remain the end-to-end goal in every phase.

1. **Resolve policy and prove coverage with bounded evidence.** Agree initial defaults, companion-change semantics, temporary versus saved controls, locale/variant choices, fallback and shared-link/export scope. Use existing report evidence and named-title read-only samples; do not scan production aggregates. Verify current Windmill bindings and whether image lists are all-language. Record field-level coverage on representative movies/shows, especially blanks and regional variants.
2. **Create the locale/metadata boundary and draft preview contract.** Validate canonical locale tags and map to upstream language/translation region without conflating availability. Implement pure draft preview and deterministic field resolution, returning provenance. Add server-visible guest persistence and consistent member resolution; add `language_default` or a versioned preference envelope as appropriate. Establish one Apply boundary with proven all-or-nothing behavior if required. Keep link/mode storage policy replaceable until UX decisions are accepted.
3. **Wire every production surface to the boundary.** Details + shared cards first as reusable modules, then direct readers in the inventory: search provisional/final/fallback, palette, related/collection, legacy grids, library/My shows, home/taste, person credits, Explorer, share lists and exports under agreed policy. Update every localized response/query/prefetch/cache key together. A card/detail slice is a useful integration milestone, not permission to call the remaining surfaces complete. Titles/posters/overview/tagline are handled together by the shared resolver.
4. **Backfill and name recognition only where evidence requires it.** Existing movie/show translation/image schemas may suffice. Recopy known Mongo rows to Crate if gaps are copy-related; refetch named titles if upstream data was never collected. Update scoped stale-row handling before any filtered-image ingestion. Add alias sidecar/index with versioned builds and full canonical/original recognition. No display-only dense-vector rebuild. If episode/season metadata is included, add keyed locale tables, ingest dedicated translations and backfill separately; if localized exports are included, extend render fonts and locale image identity.
5. **Validate and release consistently across roles.** Exercise guests/members, SSR/CSR, cache isolation, race handling, preview/apply/cancel, alias search and library sort. Measure bounded batch-read cost, cache cardinality and font/landing-page budgets. Roll out page/search role compatibility and ingestion versions deliberately. Define rollback that restores old reads without deleting collected translations or user choices.

**Migration/backfill checklist:** no new column is needed merely to add a key/value setting; regional support requires replacing two-letter-only normalization and cache grammar. Old localStorage country needs compatible migration; account/guest transfer needs a language decision row. Cache namespaces/policy version must change. Missing translation data is not a catalog-absence marker. Original/canonical names must remain available for identity, aliases, slugs and ranking. Existing blanks should not be mass-filled. Episode translation schema and full alias retention may require schema changes if accepted; verify Crate schema deployment, not just Python model edits. Region/script discrimination for posters is unavailable in current upstream image tags and cannot be repaired by a schema migration alone.
