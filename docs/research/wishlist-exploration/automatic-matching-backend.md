# Batch wishlist candidate matching

Code inspection: 2026-10-18, matching checkout `a3954d76`. Proposal only; this research agent made no catalog queries or implementation changes. Aggregate findings below come from the root agent's separate bounded read-only evaluation of the 77-title export; they are retrieval evidence, not a measured identity accuracy rate. No private titles or IDs are included.

## Recommended seam

Automatically retrieve and rank candidates for every eligible source group, prioritizing an audited native-provider-ID crosswalk, then let the member accept the proposed targets together and correct exceptions. Reuse the existing resolver after review. This removes 77 separate searches without treating title similarity as verified Netflix identity. The current resolver accepts up to 100 choices, so 77 reviewed groups fit one request, subject to its existing 32 KiB body limit ([validation and resolver](../../../goodwatch-webapp/app/server/imports/wishlist-resolution.server.ts)).

Keep suggestions outside the effective import observations until acceptance. Original media type remains `unknown`; native Netflix IDs remain source evidence. A suggestion must not create `wishlistResolution`, remove an unmatched problem, or imply that an unavailable title was found. Existing explicit member choices take priority and are never overwritten by a new suggestion run. After acceptance, existing server validation creates a fresh child preview, preserving source snapshots and parent pointers; Confirm, receipt, and Undo remain unchanged ([resolver/projection](../../../goodwatch-webapp/app/server/imports/wishlist-resolution.server.ts), [source eligibility/grouping](../../../goodwatch-webapp/app/server/imports/wishlist-evidence.server.ts), [public service](../../../goodwatch-webapp/app/server/imports/service.server.ts)).

## Observed 77-title retrieval results

Root's initial production-shaped title/original-title search returned ten candidates per type, 154 queries total: 27 rows had one exact name within the retrieved set, 29 had multiple exact names, and 21 had no exact name; none had zero candidates or failed retrieval. Elapsed time was 7,611 ms. An exact name within this capped set is not global uniqueness.

Root then queried Netflix offer links only for those candidate catalog IDs, using 35 read-only SELECT batches of at most 40 IDs and a 5,000-row cap per batch. It read 9,346 offer rows; none hit the cap. Strict direct Netflix `/title/ID` parsing plus one allowlisted JustWatch redirect wrapper parsed 9,265 links. Comparing the captured native ID with those links produced 59 of 77 rows with one typed target **within the candidate set**, zero with multiple targets, and 18 without a candidate-native-ID match; elapsed time was 11,440 ms. Direct canonical URL equality alone found zero matches: wrapper-aware ID parsing materially changes recall. These checks read local stored links; they do not follow redirects or contact Netflix.

For the remaining 18, root additionally queried exact indexed translated and alternative names: ten rows had one alias candidate, seven had multiple, and one had none. Native Netflix IDs in those candidates' stored offer links corroborated 16 of these 18 rows, with zero ambiguous ID matches or capped queries. Together the two experiments produced **75 of 77 native-ID-backed candidate proposals**, leaving two for further review. This is candidate retrieval coverage, not verified match accuracy or global uniqueness; multiple exact aliases are resolved only within the retrieved offers. Root is recording the consolidated evaluation separately.

Primary evaluation artifacts remain outside the repository: root's `wishlist-browser-validation/measure-netflix-candidate-crosswalk.mjs`, `netflix-candidates-aggregate.json`, and `netflix-candidate-crosswalk-aggregate.json`. The checked-in [streaming availability schema](../../../goodwatch-flows/windmill/f/sync/models/crate_schemas.py) establishes the underlying typed catalog ID, service ID and `stream_url` fields. The numbers support prioritizing provider identity over title ranking; they do not establish that all 59 choices are globally collision-free or correct. Candidate restriction can hide an opposing target and miss a title entirely.

For a reusable production crosswalk, normalize provider IDs at ingestion or in an explicit audited derived index keyed by provider plus native ID, recording typed canonical targets, provenance and freshness. Current `stream_url` stores complete URLs; do not assume it already provides an indexed native-ID lookup, and do not add request-time catalog-wide scans or URL substring matching. Audit all relevant stored Netflix offers for native-ID collisions across both media types, country duplicates, aliases and missing canonical targets before treating a mapping as authoritative. Deduplicate repeated country/offer evidence for the same canonical work; keep distinct canonical targets as conflicts. A candidate-scoped crosswalk can ship sooner as a **review suggestion signal**, clearly retaining that restricted-coverage status. A global collision audit is an explicit remaining requirement, not something the 59/77 measurement performed.

The smallest useful first slice is therefore the bounded alias/catalog-candidate → stored-offer-ID join, with bulk review through the existing resolver. It does not require a new persisted map or schema migration to generate these proposals. Fetch offers by bounded typed candidate-ID batches and service ID, mark row-cap/deadline hits incomplete, and compare strictly parsed native IDs. A materialized crosswalk is a later improvement for direct lookup, candidates missed by every name lane, repeat-query cost and global collision evidence; it is not a prerequisite for the review-only first slice. Its write/refresh design and full audit need separate authorization and implementation work.

The strict parser should accept only trusted HTTPS Netflix title URLs or one documented allowlisted JustWatch `/a` wrapper with exactly one redirect parameter; validate credentials, origins, ports, controls, path and positive numeric ID before retaining the identity. Do not fetch the URL, recursively unwrap, accept arbitrary redirectors, use playback IDs, or infer TMDB from provider digits. Preserve the original capture evidence; crosswalk provenance belongs to server suggestion data. Synthetic adversarial tests and observed safe wrapper shapes must define this new parser before reuse of the scratch experiment.

## Retrieval and ranking proposal

1. Load the owned preview once per batch. Select originally valid unknown wishlist groups using existing source/profile/source-ID grouping; title-only rows remain separate. Query an audited provider/native-ID crosswalk first when available; otherwise retain candidate-scoped provider corroboration as a restricted suggestion lane. Derive fallback query text from immutable originals on the server, not caller-supplied title strings. Deduplicate identical query work within the batch without merging source groups. Conflicting title variants within a native-ID group remain evidence for review rather than silently choosing one variant.
2. Retrieve candidates from movie/title-original and show/title-original, plus indexed `translation.title` and `alternative_title.title`. Exact phrase retrieval comes first, then a bounded fuzzy fallback when useful. For candidates with a captured Netflix native ID, retrieve their stored Netflix offers and compare parsed provider IDs before lexical ranking. Keep match provenance: actual matched name, lane, language/country where present, native-ID corroboration scope, exactness, similarity, and supplied-year agreement. Do not derive a year/type by parsing digits or words out of the captured title. Alternative names alone are a lower-trust name lane, and the current copy path keeps only one alternative title per country, so that lane is incomplete ([copy source](../../../goodwatch-flows/windmill/f/sync/copy/tmdb_details.py)).
3. Canonicalize typed IDs, merge candidate evidence, and batch-fetch canonical local catalog rows. Reject missing canonical targets; use authoritative title/year/IMDb/poster from the selected catalog row. Exclude adult rows consistently with existing wishlist search. Do not require a poster, popularity, score, fingerprint or current Netflix availability: those would remove legitimate personal-list entries. Do not equate a streaming provider's ID with TMDB.
4. Rank both media types together: audited unique provider-native identity first, candidate-restricted provider corroboration explicitly distinguished, then strict whole-name equality, folded whole-name equality, and phrase/fuzzy candidates. Provider collisions remain conflicts, not a popularity contest. An exact translation is strong name evidence; weak canonical prefixes must not automatically outrank it merely because the alias is localized. A supplied trustworthy year can distinguish candidates; absence of a year is not evidence. Popularity is only a deterministic display tie-breaker. Preserve remakes, same-name movie/show pairs, shorts/features, and distinct same-title/year works as separate alternatives. No numeric percentage should be presented as identity confidence without calibration.
5. Return at most five review candidates per group, with an optional preferred candidate and machine-readable reasons. A single exact hit may be preferred, but still requires the member's acceptance: bounded retrieval and an incomplete catalog cannot prove global uniqueness. Shared exact names, competing typed candidates, truncated retrieval, conflicting variants and weak fuzzy results require explicit review. On acceptance, submit existing `{choices:[{index,target:{mediaType,tmdbId}}]}`; the server repeats exact local validation. Null clears and existing delta semantics continue to work.

Canonical candidate deduplication happens before ambiguity ranking. Effective wishlist deduplication remains in [preview creation](../../../goodwatch-webapp/app/server/imports/preview.server.ts): iterate original source order, suppress duplicate effective typed IDs before per-title conflicts, retain immutable originals for later changes. Two different Netflix IDs may legitimately map to one catalog work; apply it once while keeping both pieces of source evidence.

## Proposed read-only batch contract and bounds

Add a dedicated endpoint such as `GET /api/imports/:id/suggestions?offset=0&limit=20`, after agreeing the route with the UI owner. Offset is over existing eligible source groups; limit is 1–20. No uploaded titles, arbitrary SQL, or caller candidate metadata. Return:

```ts
{
  importId: string,
  algorithmVersion: string,
  offset: number, total: number, hasMore: boolean,
  groups: Array<{
    representativeIndex: number,
    state: 'suggested' | 'ambiguous' | 'no_candidates' | 'unavailable' | 'already_resolved',
    preferredTarget: { mediaType: 'movie' | 'show', tmdbId: number } | null,
    candidates: Array<{
      mediaType: 'movie' | 'show', tmdbId: number,
      title: string, year: number | null, posterPath: string | null,
      evidence: Array<{ lane: string, matchedName: string, language?: string }>
    }>,
    truncated: boolean
  }>
}
```

This response is a proposal, not an existing API. Keep full original/private journals out of it. Reuse existing matching-group data for original source display. Treat failures separately from successful empty retrieval; do not catch a failed alias lane as proof of no ambiguity. If a useful lane fails, flag the group `unavailable` or incomplete and keep any partial candidates reviewable.

Suggested starting limits: at most four groups concurrently, at most four indexed name lanes per group, 1,500 ms per group with real abort propagation, and an eight-second request deadline. Cap each retrieval lane at 20 plus one overflow sentinel, alias-to-target IDs at a fixed total, and returned candidates at five; overflow sets `truncated` and prevents uniqueness claims. Stop launching work at cancellation/deadline, mark unfinished groups unavailable, and allow retry. These are proposed limits requiring latency/load validation, not measured capacity. Four automatic pages cover 77 groups; no 77 manual searches are required. Avoid a single unbounded OR query where one generic title can exhaust the shared limit and starve other rows.

Cache successful bounded retrieval only within a request initially. Any later cache needs bounded size/TTL and algorithm/catalog-version invalidation; private query strings must not appear in SQL logs, telemetry, URLs or shared unscoped cache keys. The proposed URL carries only owned import pagination. Existing resolutions are revalidated on every child preview; stale suggestion data never authorizes a missing target.

## Meaningful implementation tests

Use the existing public `previewImport → suggestions → resolveWishlistImport → confirmImport → receipt → undoImport` seams and fake catalog transport from [resolution tests](../../../goodwatch-webapp/app/server/imports/wishlist-resolution.server.test.ts), plus request validation in [HTTP tests](../../../goodwatch-webapp/app/server/imports/wishlist-resolution-http.server.test.ts). Add behavior tests before implementation:

- A batch of 77 synthetic unknown rows yields bounded pages, both media types and finite query concurrency; retrieval performs no source/member mutations. One reviewed bulk choice request creates the expected child preview.
- German localized name absent from canonical/original fields retrieves the same canonical work via translation, preserving original unknown evidence. Missing aliases and lane timeouts remain distinguishable from no candidates.
- Same-name movie/show, remakes, same-title/year distinct works, short generic titles, and missing years stay ambiguous; popularity never establishes identity. Unicode/diacritic/possessive/space folding collisions do not disappear.
- Canonical/retired IDs and several translations of one work yield one candidate with canonical display metadata. Separate source IDs remain separate groups; repeated source IDs propagate a reviewed choice consistently. Two groups choosing the same target apply once in source order.
- Direct provider URLs and one valid wrapper yield the same native identity without a network request. Duplicate redirect parameters, untrusted hosts/ports/credentials, control characters, malformed IDs, nested wrappers and playback-only links fail closed. Multiple countries for one canonical work collapse; a provider ID on distinct typed canonical targets remains ambiguous even when one is more popular or outside the title candidate set. Audit truncation or missing scope never masquerades as global uniqueness.
- Exact versus fuzzy/partial names, sequels and numeric title text preserve identity distinctions; one-character and over-100-character source titles are not silently truncated into another query. Define explicit bounded unsupported-query behavior rather than inheriting current manual query limits unnoticed.
- Query caps/overflow, abort, cancellation, adult policy, missing canonical targets, foreign/expired previews and historical missing snapshots fail safely without exposing journals. A stale or forged suggestion target still undergoes existing exact resolver validation.
- Existing member choices survive reruns; clear restores source unknown state. A selected target disappearing before preview creation cannot fall back to source IMDb/title/year. Receipt, skipped CSV and Undo retain consistent chosen catalog identity and untouched original evidence.

Before shipping the review-only slice, evaluate the actual 77-title export privately with member-reviewed reference targets. Before claiming authoritative provider mappings or allowing unattended application, also complete the global provider collision audit. Report only aggregate candidate recall, preferred-candidate errors, ambiguity/no-result rates, latency and query counts. Do not claim a verified completion percentage from exact-name or candidate-restricted provider matches alone. Live Netflix capture completeness remains a separate question.
