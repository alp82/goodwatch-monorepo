# Existing watchlist tools and authorized import routes

Research for [#733](https://github.com/alp82/goodwatch-monorepo/issues/733), under [#702](https://github.com/alp82/goodwatch-monorepo/issues/702). Sources checked **2026-10-20**. Publication/revision dates appear where the source supplies them; otherwise the date is this read date. **Research and product recommendations, not legal advice.** No accounts were linked, provider sessions accessed, personal archives collected, or import journeys exercised.

## Finding

**No reviewed tool establishes a quick, authorized, complete bulk import of Netflix, Prime Video and JustWatch personal watchlists into GoodWatch.** The strongest current commercial lead is Younify Connect, which now advertises a watchlist API. Its own terms expressly disclaim affiliation with streaming providers and require compliance with their terms; a Trakt–Younify partnership does not fill that permission gap.

The routes supported by positive provider documentation are narrower: existing tracker APIs and original export files, Netflix's asynchronous privacy archive, Amazon's personal-data request, and Netflix's **single-title Share** action. Plex publishes a real watchlist RSS feature for its own list. Google TV and Apple TV offer genuine integrations within their ecosystems, but their public documentation does not expose a reusable bulk personal-provider-list export for GoodWatch.

This builds on [#732's resolution and source-terms report, pinned at 00a5f2fb](https://github.com/alp82/goodwatch-monorepo/blob/00a5f2fb7d31ff4b9f237acdb7d765b47023a5a3/docs/research/wishlist-exploration/source-terms.md). That file is on `research/source-terms`, not main. Its Netflix, Prime and JustWatch extraction holds remain the baseline; this survey found no documented exemption that reverses them. Local processing, one click, a browser-store listing and an open-source license are not provider authorization. Existing [tracker research](tracker-routes.md) and [alternative routes](alternative-routes.md) supply implementation detail; earlier bookmarklet prototype suggestions are superseded by the terms hold for member shipment. Owner Q31 permits only official routes to members; owner-account experiments are a separate scope.

## Browser exporters: convenient mechanics, no demonstrated exemption

The [Netflix Watchlist Manager repository](https://github.com/timbillapp/netflix-watchlist-manager), read 2026-10-20, describes automatic title scanning, injected scripts, JSON export and automated restoration through page navigation/clicks. Its MIT license permits using its code; it does not license Netflix access. Published export journey has six actions after installation. Restoring 600+ items is advertised as 40–50 minutes: “no API required” does not mean no automation. Completeness remains a publisher claim, constrained by availability and page loading.

The [Universal Trakt Scrobbler repository](https://github.com/trakt-tools/universal-trakt-scrobbler/blob/master/README.md), read 2026-10-20, supports browser **history/scrobbling** for Netflix and Prime among others. Do not treat that as full personal-wishlist import. [SIMKL's first-party Netflix instructions](https://support.simkl.org/knowledgebase/articles/735609-how-can-i-import-my-watch-history-to-simkl-from-ne) also describe history, and prior [distributed-code inspection](tracker-routes.md#official-netflix-enhancer-inspected-distribution-history-only) found private viewing-activity requests rather than My List. JustWatch→Letterboxd scripts listed by Letterboxd are helper references, not JustWatch endorsements.

The survey did **not establish a primary-source Netflix/Prime/JustWatch account-ban case or provider takedown caused by these specific tools**. This is a search result, not a claim of zero incidents or low risk. A concrete access restriction exists elsewhere: [SIMKL's current Trakt importer](https://simkl.com/apps/import/trakt/) says, “Trakt has blocked SIMKL's access to its API”. That is SIMKL's firsthand report of an **integration block**, not a verified member-account ban or Netflix enforcement; its ZIP import survives. [SIMKL API rules](https://api.simkl.org/api-rules) separately reserve client suspension for sustained overages. Distinguish reserved remedies from observed enforcement and an API block from an account termination.

## Official files and deliberate shares

**Netflix privacy archive:** [official information-request help](https://help.netflix.com/en/node/100624), read 2026-10-20, allows up to **30 days after request verification**. The help does not contractually specify `MyList.csv` columns, snapshot time, current membership, removals or native title IDs. The historical Bionic parser in #732 is evidence of an importer, not a current Netflix file guarantee. Estimated journey: request/sign-in/verify, wait, download, select profile/file, upload and confirm (~6–8 operations). Reuse [#640](https://github.com/alp82/goodwatch-monorepo/issues/640) for real files and [#622](https://github.com/alp82/goodwatch-monorepo/issues/622) for the native adapter. Immediate [Viewing Activity CSV](https://help.netflix.com/en/node/101917) is history, not wishes; it does not solve the My List problem.

**Amazon Request your data:** [Amazon's own help host](https://digprjsurvey.amazon.com/csad/help/node/TP1zlemejtTn6pwYKS), read 2026-10-20; main amazon.com help retrieval was unavailable. Amazon documents request page → sign in → categories → submit → confirmation email → secure download. Exact excerpt: “Download your data using the secure link sent to your email address when ready.” Add GoodWatch upload/profile review: estimated **7–8 operations**. The page supplies no delivery SLA, Prime Watchlist schema, stable IDs or guarantee of complete current membership. **Prototype only the archive evidence check first**; no invented `Watchlist.csv` contract. IMDb's [Watchlist FAQ](https://help.imdb.com/article/imdb/track-movies-tv/watchlist-faq/G9PA556494DM8YBA) treats its list as separate from Prime Video: IMDb CSV is not a workaround for obtaining Prime wishes.

**JustWatch personal-data request:** [privacy policy §17.2](https://support.justwatch.com/article/privacy-policy) provides an official portability/request channel. No current sample or guaranteed personal-Watchlist file contract was established. Ask for existing wishes and list identity, separate seen/ratings, snapshot time and removals; verify what is actually delivered. This is asynchronous discovery, not a documented one-click export.

**Netflix single-title sharing:** [Netflix's official mobile help](https://help.netflix.com/en/node/464), read 2026-10-20, says: “Tap Share.” Then: “Choose the app you want to use and complete the share through that app.” A GoodWatch receive/paste-link prototype can accept the **already shared title URL**, parse its native ID locally, show a match and ask whether it is Want to See. No provider page fetch/observer/clicker is needed. Roughly **3–4 operations/title** including review; initial app-target setup may add steps. This is fast for a few titles and future discoveries, **O(n)** for a backlog, and has no history/ratings/current-list completeness claim. A shared title is not proof it was in My List or that the member wants it: confirm intention.

**Custom-list links, email and share sheets:** JustWatch's custom-list help permits sharing with people; Netflix documents title shares. A title URL can carry identity while an email/pasted text carries user-supplied names. Neither grants a generic bulk URL reader permission. Do not add authenticated fetches behind a “paste link” label. No provider-issued full-list email import contract was found. A receiving share target is a delivery feature to validate on each supported browser/OS, not assumed existing GoodWatch functionality.

**Screenshots/OCR:** No reviewed named tool's primary documentation established a provider-authorized full streaming-Watchlist OCR export. Processing an already supplied image is technically different from accessing an account, but permission for automated screen capture is not established. It loses IDs/years, can omit offscreen titles, requires multiple images plus matching review and cannot prove removals or completion. A manual text fallback can help, but do not label OCR “compliant” merely because it avoids private endpoints or make it the default low-step route.

## Regulatory portability: useful request basis, not a live API grant

The [EDPB's official portability guidance](https://www.edpb.europa.eu/sme/be-compliant/respect-individuals-rights_en), read 2026-10-20, requires consent/contract-based processing, automated processing and data supplied by the person, including observed behavior. It discusses machine-readable XML/JSON/CSV with needed metadata and direct transmission when technically possible. Its example: “Your customers can request the transfer of their song lists to another music streaming service.” **Inference:** member-created watchlists are a plausible portability request subject; applicability and exact data scope need provider/legal assessment. Article 20 does not establish an immediately available universal streaming-watchlist API, complete catalog rights or permission to scrape while waiting for a response.

The [European Commission's Data Act explanation](https://digital-strategy.ec.europa.eu/en/factpages/data-act-explained), read 2026-10-20, dates application to September 12, 2025 and explains connected-product/related-service data. In its smart-TV example, “the film itself is not within scope”; screen-brightness data illustrates the connected-product category. Cloud switching is another part of the regulation. **Inference:** a TV integration does not by itself put every streaming-account Watchlist under a mandatory real-time export right. Do not promise Data Act authorization or infer a third-party extraction exemption from it.

## Recommendation and prototype acceptance gates

**Keep official APIs and original files as the default. Prototype intentional Netflix title sharing and validate an Amazon archive; do not adopt a scraper behind a commercial intermediary or local-file label.** For existing tracker users, existing supported files/connections avoid another account and migration hop. A streaming-only member should not have to create Trakt, SIMKL or Reelgood just to pass an export to GoodWatch.

1. **Quick share → Want to See prototype:** accept an intentionally supplied Netflix URL; perform no online provider read; preserve native ID; show candidate/review; confirm Want to See explicitly; leave Seen/scores untouched. Measure steps on desktop/mobile, unsupported share targets and ambiguous/local-offer matching. A few titles should be quick; never advertise it as bulk My List sync.
2. **Amazon archive evidence ticket:** have the owner request the minimum relevant categories; keep originals/household data out of Git. Establish whether Prime wishes exist, selected-profile scope, schema/dictionary, timestamps, removals and stable IDs. Only a positive sample result earns an adapter implementation ticket. Do not build from imagined CSV names.
3. **Official tracker readers:** continue MDBList sample gates and use existing [#616](https://github.com/alp82/goodwatch-monorepo/issues/616)/[#621](https://github.com/alp82/goodwatch-monorepo/issues/621) for a scoped SIMKL own-wishes reader under its current API rules; [#618](https://github.com/alp82/goodwatch-monorepo/issues/618) already covers IMDb. These tickets remained open on the read date. Preserve explicit intention, source IDs/type, profile/list scope and matching review. An empty/error/premium-only response never means the person's Wishlist is empty. Do not add a new streaming extraction dependency.
