# Prime Video Watchlist: route decision and bounded experiment

Research date: 2026-10-18. Resolves [Which read-only Prime Video route can capture the intended Watchlist?](https://github.com/alp82/goodwatch-monorepo/issues/705), within [Map: streaming wishlist imports](https://github.com/alp82/goodwatch-monorepo/issues/702). Research only: no signed-in sample, provider request replay, account mutation, extension installation or GoodWatch import was performed. No upstream implementation was copied.

## Decision

**Prototype a user-opened Watchlist with selected hydration-state extraction first, continuous DOM accumulation as the independent comparison, and observation of actual list responses only if state does not expose the continuation boundary.** Follow the member's own navigation on their actual origin; do not hard-code `/region/na/watchlist`, invent an endpoint contract, or adopt the Kodi client/session machinery. Current source provides concrete Watchlist/category/pagination leads, but no route has a demonstrated current signed-in success or completeness claim.

A successful next experiment must establish both saved membership and identity. It may conclude that only partial capture is supportable. Defer a production Prime adapter and any general regional support claim until that evidence exists. This resolves the research question; the separate HITL prototype and owner acceptance remain open.

This is consistent with [CONTEXT.md](../../../CONTEXT.md) and [tracking ADR](../../adr/0009-tracking-is-a-state-machine.md): captured wishes are candidates for Want to See, not watches, show progress or activity now. Preserve Seen and rewatch semantics through the existing additive import boundary.

## Verified public boundaries

Prime's own profile help says each profile has separate Watchlist, season progress and recommendations. Account-level authentication alone therefore does not establish the selected list. Record a locally visible profile confirmation; do not publish its real name or account identifiers. [Prime Video profile help](https://www.primevideo.com/-/nb/help?nodeId=GD8VJD2EDJ2GSNEC&tag=europe1-f3).

IMDb explicitly says its Watchlist and Prime Video's are separate. An IMDb CSV is not a substitute for this investigation. [IMDb Watchlist FAQ](https://help.imdb.com/article/imdb/track-movies-tv/watchlist-faq/G9PA556494DM8YBA).

Amazon's published Data Portability scope catalog describes its `lists` scope as occasion lists; gift lists, digital orders and Fire TV events are other categories. The inspected catalog does not establish a Prime Watchlist membership export. That is a limited negative finding, not a claim that a personal data request cannot contain one. No current archive with a verified Watchlist schema was obtained; do not invent filenames. [Amazon scope catalog](https://developer.amazon.com/docs/amazon-data-portability/available-scopes.html).

## Actual extractor evidence

All source links below pin inspected commits. A recent commit is evidence of source availability, not of working provider support.

### Amazon VOD/Kodi: strongest structured route lead

Inspected Sandmann79/xbmc at `bfb3940ec796166f50b0c2beca9a8ee779689e5e` in a disposable clone. This materially improves on the older notes, which only established hydration scripts on a non-Watchlist page.

- **Navigation and membership boundary:** `BuildRoot` discovers a Watchlist link from `yourAccount.links`, older `mainMenu`/`lists` variants, or `nav.navigationNodes` under My Stuff. It distinguishes `watchlist` from `library`; one fallback synthesizes subpaths, so it is a lead to compare against actual navigation, not a contract to copy. [web_api.py, navigation](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/web_api.py#L322).
- **Categories and mixed entities:** the My Stuff branches parse `subNodes`, `view-filter` filters and offer filters before extracting entities/items. A Watchlist view is not necessarily all My Stuff or all offers. Per-item branches inspect `watchlistAction`/`watchlistButton.endpoint.query.titleType`, distinguish season/show from other entities, and handle live stations/events separately. A GoodWatch reader must union movie and show categories and exclude library, recommendations and live entities; a generic `/detail/` anchor does not prove membership. [web_api.py, My Stuff and extraction](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/web_api.py#L1400).
- **Pagination:** branches handle `nextPageStartIndex < totalItems` plus `seeMoreHref`, typed NextPage paginator links, token/query-parameter pagination, `hasMoreItems` with start-index advancement, and collection pagination fields. These coexist as compatibility branches; they do not prove which current Watchlist layout uses which form. Some construct private API URLs and use fixed increments. Observe first-party continuation instead of replaying those constructions. [web_api.py, pagination](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/web_api.py#L1474).
- **State extraction:** `GrabJSON` accepts API JSON and parses HTML JSON/template scripts, admitting scripts without IDs or with `hydration-data` in the ID. It merges objects. GoodWatch should instead allowlist exact list paths and return only the required fields; arbitrary recursive merging expands the privacy and membership boundary. [network.py](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/network.py#L311).
- **Identity:** detail processing distinguishes GTIs (`amzn1.dv.gti.*`), compact GTIs, ASINs, links, `titleType`, and season/show relationships. It sometimes fetches detail pages and synthesizes show/season structures. Retain the original membership entity ID and namespace, origin, canonical detail path, observed type and explicit parent relation separately. Never label every `/detail/` identifier an ASIN, treat a season as a whole-show ID, or equate Prime IDs with IMDb/TMDB IDs. Detail metadata alone establishes no saved membership. [web_api.py, identity processing](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/web_api.py#L970).
- **Regions:** territory setup contains Amazon DE/UK/US/JP origins and several Prime Video marketplaces, and can derive website/base URL from startup territory config. This demonstrates why `primevideo.com` alone is insufficient as a global assumption; it is not an exhaustive or current supported-origin list. Start with the owner's observed domain and route; require a separate fixture/measurement for another layout. [login.py](https://github.com/Sandmann79/xbmc/blob/bfb3940ec796166f50b0c2beca9a8ee779689e5e/plugin.video.amazon-test/resources/lib/login.py#L31).

The Kodi package declares GPL-3.0-or-later and substantial Python/Kodi dependencies; it also contains login, playback and Watchlist mutation functionality. ## Mechanism comparison and permissions

| Mechanism | Value | Boundary / stop condition |
| --- | --- | --- |
| Selected inert JSON state | IDs, type, explicit category and pagination hints without reading app globals | May contain only the first page or unrelated account state. Require observed Watchlist ownership of each collection. |
| DOM accumulation | Independent visible-membership reference; can run with temporary active-tab access | Capture continuously while the actual list container scrolls; unchanged height/count is only no progress, never proof of exhaustion. |
| Actual response observation | Can expose page entity IDs, totals and continuation that DOM hides | Arm before first-party navigation; filter exact observed list responses and reject unknown schemas. Login redirects, missed initial requests or cursor gaps mean partial/unknown. |
| Personal archive | Could avoid page instrumentation | No verified current Watchlist schema/sample; defer adapter, retain as a future sample route. |

Chrome documents temporary `activeTab` access after a user gesture and content scripts' isolated execution world. Inert JSON in the DOM can be read without MAIN-world access; a page-global response hook requires a narrow MAIN-world bridge and can miss requests made before installation or outside patched APIs. Do not assume `webRequest` exposes response bodies: Chrome's API exposes lifecycle events and headers. A debugger permission is disproportionate for this first experiment. No cookies, persistent all-site access, request rewriting or session export is needed for the proposed state/DOM reader. [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [webRequest](https://developer.chrome.com/docs/extensions/reference/api/webRequest).

## Exact smallest authorized sample and prototype

1. On one consenting adult profile, use the site's own navigation to open Watchlist on its actual regional origin. Record browser/version, locale, redacted route, observed selected profile, category/offer filters and any visible totals. No profile creation, switching via private endpoints, adding/removing entries or playback is required.
2. Privately record a reviewed membership reference by navigating every Watchlist movie/show category and continuation until an explicit end. Prefer an existing list spanning at least two pages with both a movie and show; include existing unavailable, season-level or duplicate-listing examples if present. If absent, mark these cases untested rather than manufacture them. A list smaller than one page cannot validate pagination.
3. Inspect exact hydration script and selected list-subtree names locally. Capture the first page, first continuation and terminal response/state with surrounding category/total/end flags. Record only field names/shapes and synthetic values publicly. The raw HTML/HAR/global state stays outside Git/issues; redact customer/profile IDs, cookies, tokens, signed URLs and account labels. Even cursor values stay private; publish their presence and progression only.
4. Build a throwaway local reader against synthetic fixtures derived from those shapes. Preserve source entity namespaces, title, explicit media type/year/parent if present and credential-free detail paths. Produce shared wishlist JSON v1 only for entities proven to belong to Watchlist. Keep uncertain season-to-show normalization reviewable; no title-only merge.
5. Compare state membership with continuous DOM accumulation during the same traversal. If state lacks continuation evidence, inspect only the browser's already-issued list responses. Stop on challenge, unknown schema, changed profile/origin/filter, repeated cursor, timeout or safety cap; emit partial/unknown with reason. Do not add endpoint replay or detail-enrichment requests merely to turn this into a larger client.
6. Owner evaluates the result and scope in the dependent HITL prototype. This research supplies no owner verdict, import confirmation, store-distribution decision or production acceptance.

## Candidate gates to agree before measuring

For the one measured account/layout, require exact membership equality against the reviewed reference, zero contamination from library/history/recommendations, no unexplained identity loss/conflicts, coverage of every selected movie/show category, and an observed terminal boundary for every pagination chain. Record source reference size, captured unique native entities, overlap/misses/extras, duplicate conflicts, page count, first-party requests, any added requests, elapsed time, steps and stop reason. Report capture recall only when the reference denominator is known. Unknown/unavailable membership and missing categories remain explicit limitations.

Synthetic regression cases should cover a mixed movie/show list, separate library/recommendation collections, two pages plus terminal state, duplicate titles with distinct IDs, repeated cursor, missing continuation, profile/filter change and a season with/without explicit show parent. A deliberate stop must never report complete. Matching precision/coverage/abstention is measured separately against reviewed GoodWatch matches; a complete capture cannot prove a correct match. No percentages or live capability are established by this report.

**Follow-up scope:** the existing Prime HITL prototype can now test this bounded route. Additional regional fixtures or a personal-export sample are follow-up proposals to the map owner, not preapproved build tickets. Production implementation remains dependent on that evidence and owner acceptance.
