# YepWatch shared room description

Status: implemented locally, pending the stopped-writer database migration and owner deployment.

A YepWatch room has one country and one explicitly chosen set of streaming services. Participants do not create, choose or join playback screens. The host edits the shared selection. Its initial provider default is the deduplicated union of active linked participants’ saved GoodWatch providers, filtered to providers offered in the chosen country. The public default exposes no per-person attribution. An explicitly saved room selection is not silently overwritten by later joins, linking, dropping or returning; the host can choose “Use everyone’s saved services” to apply the current union. Unlinked/unavailable accounts contribute no defaults. The existing typed member preferences supply the default, so no second provider-preferences table is added. The database stores `country`, `service_ids` and `services_confirmed` directly on `yepwatch_room`; `yepwatch_screen`, participant `screen_id`, room `screen_records` and availability `screenId` columns are removed. The old wire/catalog adapters temporarily derive a singleton `room` context for installed clients. This is compatibility data, not a persisted or selectable screen.

The host can write a prompt, use a small preset, or dictate through the device keyboard. GoodWatch's existing search role runs its Jev interpretation and ranking with the room's country and providers. The prompt, reading attributes and bounded ranked title keys are published together with the settings in the room's normal CAS. Failure keeps the prior description and settings. Committed command retries reuse the receipt. No query model, second Jev implementation, account database or issuer is embedded in YepWatch.

The interpretation is a declared `OBJECT(STRICT)` with `prompt`, typed `attributes`, `rankedKeys` and `interpretedAt`, not a generic payload. The shared projection includes prompt/attributes only. Start and subsequent pages intersect the ranked titles with the eligible catalog and apply existing media-kind, availability and saved-progress rules. Suggestions are a bounded search result (currently 100 ranked titles), not a promise to enumerate every matching title. Exhausting it does not silently switch back to an unrelated popularity list. Restart retains the room description; explicitly saving an empty prompt clears it.

Leave is an explicit room command. The person remains in the roster with a visible Dropped marker but ceases to count toward matches and agreement; disconnected people still count until they explicitly leave. Hosting passes to the first active participant. Leaving invalidates that actor's realtime lease, removes pending admission tickets and account connection intents, and preserves receipts and answers. Reopening the invitation with the saved browser cookie or native credential restores the same identity, nickname, votes and card position. No new place is allocated, even after a lost return acknowledgement. Rejoining an unfinished room makes the participant required again; a completed decision is never reopened. Previous agreement survives only for its original proposal version. If everyone drops out, the room and cards stay intact until their existing expiry. New identities remain subject to the existing 12-place limit; a return does not consume another place. Without the original device credential, an invitation alone cannot reclaim someone else's saved identity.

GoodWatch sign-in links the existing guest actor to the existing central account after explicit consent. Registration and environment setup are operator actions. This change does not activate the separate refresh-token work; an expired account grant requires reconnecting.

The typed storage format becomes 2. This is an internal compatibility check, not versioned table names or a new product release. The explicit migration backs up and verifies the old state, changes the typed columns, republishes converted records through CAS, verifies the complete room state and only then removes the obsolete table. Conflicting legacy country/provider contexts require an explicit operator decision before any migration writes. See [deployment steps](../../yepwatch-app/docs/room-settings-deployment.md).
