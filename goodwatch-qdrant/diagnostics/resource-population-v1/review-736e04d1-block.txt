# Verdict: BLOCK (source-only, commit 736e04d1)

Six concrete defects block the source freeze. Nothing was executed, hashed or run, so test results and every sha256 in `provenance.json` and `source-freeze.json` are unverified by me. This is not observation authorization and says nothing about production results.

## Blocking defects

1. **Auditor dimensions report "observed" for failed dimensions** — `auditor.py:130-131`
   - `sampling`, `primaryIdentity` and `requiredMetrics` are set to their positive values whenever no exception was raised, regardless of what is in `reasons`.
   - A journal with `sample-gap`, `clock-drift`, `source-or-reader-turnover`, `reader-placement` or `source-lock-or-swap` returns `observation-incomplete-or-refused` alongside `sampling: scheduled-samples-observed` and `primaryIdentity: observed-brackets`.
   - Optional dimensions collapse to `partial-or-unavailable` (also `reader.py:583-587`) with no counts or reasons, so the table's partial/unavailable split is not expressed in output (requirement 1).

2. **Auditor never reads the optional census evidence and drops the reader-exclusion proof** — `auditor.py:115-116`
   - `sshCensus`, `backupCensus` and `siblingCensus` are decided only from the reader's own label string; `sshUserspace` and `otherCgroups` are never opened.
   - A row with those objects missing, or with `complete: false`, still audits as `observed-endpoints-only`.
   - The old auditor required `ownedReaderExcludedCount == 1` (`strict-auditor-v3.py:66`); the new one has no equivalent, so the mandatory exclusion proof is optional at the audit layer (requirement 5).

3. **A census bound can become a false fatal `reader_identity_changed`** — `reader.py:287, 289, 302, 310`
   - The 4096-node cut, the 1 s deadline and the 64-process break all stop the scan early.
   - If the reader's own PID was not reached before the stop, `excluded != 1` raises `reader_identity_changed`.
   - The table maps `optional_census_bound` to dimension-partial, so one condition has two outcomes depending on enumeration order, and the retained reason is wrong (requirement 1).
   - It fails closed, but with no retry allowed it would burn the observation on a mislabelled cause.

4. **The worst-case row fixture does not cover the real row** — `test_population.py:100, 140-156`
   - The fixture row omits `sshUserspace`, `otherCgroups`, `metadataOnly` and `archiveResidentBytesMeasured`, roughly 2 KB at maximum magnitude.
   - By my hand estimate the inflated test row is about 7.8 KB, so `bound_ledgers` truncation (`reader.py:594-600`) likely never runs in any test; the `members + truncatedCount == 16` assertion holds trivially.
   - For the real schema I estimate the zero-member row at 7.7–8.0 KB against 8192, a margin within my estimating error. Requirement 9 asks for this to be shown, and it is not.
   - The member tuples used (`birth` set with `unknown` proof) are a shape the auditor rejects.

5. **Main and reader refusals carry no typed numeric or hash evidence** — `reader.py:379-380, 403-404, 478-479, 462-463, 393-394`
   - Positive main VmLck raises without `lockedBytes`, both in the fence and in the sample.
   - Reader lock and reader placement change share one bare `source_locked`, with no bytes and no group hashes.
   - The `SwapTotal` refusal and the limit/ancestor change carry no value or hash.
   - Plan line 18 and requirement 3 require typed evidence on these; only the auxiliary lock (`reader.py:432`) and the directory identity (`reader.py:377`) comply.

6. **"Byte-unchanged, proven by hash" is recorded but not proven in source** — `test_population.py:81-82`, `provenance.json:12-51`
   - The only hash assertion is on the `strict-reader-v3.py` copy.
   - No fixture checks the `strict-auditor-v3.py` copy, the two originals, the four original tests, the four idle files or `source-freeze.json` (requirement 13).
