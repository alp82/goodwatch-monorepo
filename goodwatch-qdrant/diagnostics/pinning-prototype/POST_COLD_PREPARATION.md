The new paired protocol applies the same preparation after cold startup and before the first measurement in both baseline and candidate. The request runs under the controller's already-held exclusive lock; the preparation helper validates the actual lock FD and never reacquires it. The parent and bounded writer remain outside the clone cgroup. Source/process/ancestor limits, exact cgroup and reclaim FD identity, zero swap/locked/dirty/writeback state, metadata health, disk budget and host floor remain mandatory. The optional retry window is five seconds; it accepts only a fresh zero-dirty/writeback snapshot, with existing bounded source inspection. A late snapshot fails the retry deadline. No source-file sync, global flush or dirty-page exception is introduced.

Registration refuses before acknowledgement when fourteen receipts already exist or any existing receipt is malformed. The cleanup census continues after per-record malformed/unknown evidence, examines at most twenty-eight records to cover bounded anomalies, and never calls excess evidence clean. A reused PID with different start ticks proves the original birth exited and never receives a signal. Missing or changed metadata for the same birth remains unknown; a newly opened pidfd is retained. TERM/INT are masked through owned cleanup, deferred signals are counted, and the original failure is rethrown with exit evidence.

Before any write, the child resets inherited handlers, arms parent-death TERM and waits for acknowledgement. The parent opens its pidfd, records actual parent/writer birth identities and target FD device/inode in an O_EXCL mode0600 receipt, fsyncs that receipt and its directory, then acknowledges. Parent interruption triggers owned pidfd TERM/KILL and bounded reap; unproven exit retains its pidfd and reports unknown. The outer must census the bounded unique receipts, validate birth/FD identity and protect the actual Qdrant, outer and source-parent PIDs before any adopted signal. It uses pidfd exit readiness for an adopted non-child; controller exit alone is insufficient. Receipts remain task evidence, never private query payload.

The writer makes one bare 3 GiB request, with the existing 60-second request bound and bounded TERM/KILL cleanup. EAGAIN can describe an under-reclaimed request only when the writer exited and a fresh measurement proves `current + actual selected missing bytes + 256 MiB <= 6 GiB`. The preparation records absolute counters and requires unchanged max/OOM/CPU counters, source cohort and ancestor limits. It does not credit requested reclaimed bytes. A strict preparation-final-to-first-controller-measurement counter fence and first-measurement-to-pin-before-accounting fence close admission gaps. The subsequent controller measures again and retains its strict initial-pin host and cap checks. Host MemAvailable includes reclaimable cache, so successful cgroup reclaim does not imply a matching increase in host MemAvailable.

The six-frame contract adds `cache-preparation-complete` before the existing pressure/query/cleanup frames. It validates the single writer, health, source identity, zero dirty state, clean numeric counters and actual cap fit. The native negative still requires at least 64 MiB of prequery missing selected pages, query major faults and Qdrant server time at least 1.5 seconds. The candidate still requires server and wall time below 1.5 seconds, persistent locks, clean limits, per-ID score parity and actual cleanup.
