# Prepared clone controller and comparison

These files are prepared only. Default invocations emit `prepared-only`, without Docker inspection, archive reads, process placement, pinning or queries. The prepared JSON files supply a concrete proposed configuration for review; neither is approved for execution. The controller requires the safety follow-on runtime API (`source_check`, direct-proc source validation, cap/VMA preflight and release proof). Local fixtures prove control logic, not actual foreign-cgroup placement or clone lifecycle. Combined source review, frozen configuration, resource review and the actual zero-pin turnover gate must precede full pinning and held-out capture.

Read rate is at most 64 MiB/s, duration 70–180 seconds, with sufficient time for that rate. Helper policy freezes four selected classes, lock budget, cap reserve, VMA reserve, host floors, exact image/mounts, memory and swap both 6 GiB, CPU2 and actions. Rule/code/policy freeze occurs before new held-out selection. Dynamic raw-range selection hashes describe actual file cohorts and must match across paired phases; they are not the rule hash and do not freeze contents.

Explicit controller arguments are `--execute-reviewed --phase baseline|candidate --case-tag TAG --config PATH --policy-sha256 HASH --code-sha256 HASH`. The separate `--raise-own-nofile` flag permits only each participating parent's/child's bounded soft-NOFILE raise within its existing hard limit. Raising the child's own memlock limit requires its own flag; capability-dependent RLIMIT behavior is not assumed. No production mode, search API, interpretation call, model download or history write is implemented.

## Placement and turnover gate

`turnover_gate.py` additionally requires its exact gate source SHA. It performs no pinning, mapping, archive read or cache advice. It checks the same exact clone/source policy, owner, ports, three mounts, canonical root, owned disk budget and host floor. A spawned child receives a parent-inspected Source, validates its actual proc identity without Docker subprocesses, joins only itself to the clone cgroup, and proves fresh cgroup placement plus VmLck zero. The parent remains in its original cgroup. Joining the already-running clone uses host floor max(emergency, reserve+cap reserve); the stopped-before-start gate separately retains the 5 GiB floor. Fresh join accounting must show zero cap/OOM/throttle increments. The gate stops only the owned clone and records whether the foreign child survived the grace period and its exit code; actual child disappearance is required before restart. After bounded readiness and changed Qdrant PID/start ticks, a second child independently proves placement and cleanup. Failure stops the gate; it does not authorize a full pin or assert that a stopped clone was restored on every failure path. Mock fixtures do not substitute for this actual gate.

## Cold and pressure controls

The controller uses the owned exclusive control lock and exact owner/image/resources/three bind mounts. It validates canonical archive path, FD identity and disjointness from every owned store inode before checksum/advice. Total allocated owned bytes stay below 11 GiB (inode-deduplicated), with free disk above 3 GiB. Cold control stops only the owned clone, verifies regular unique store inodes, fsyncs/advises only those stopped files, requires zero sampled resident pages immediately after eviction, then starts the clone. Readiness requires 244,262 points, 12 segments and six configured/mapped shards. Startup can repopulate pages; pre-start zero residency does not imply fully cold query data after startup.

Baseline and candidate read the same existing archive with identical bounds and checksum. The archive reader stays in its original cgroup; no archive-sized scratch file is written. Only the spawned pin child joins the clone cgroup. Parent source RPC performs every Docker inspection outside the capped child; the child separately validates actual proc identity. Fresh source/cgroup/VmLck checks, initial pin state, core nonresident-page cap fit and VMA bounds are retained. Missing capacity makes the stage inconclusive, without relaxing limits.

The actual read loop defines the pressure window. Only steady passes with no new locks or changed ranges may request the runtime's narrow clone memory.max exception. Exceptions are visible exploratory results. Clean promotion still requires zero memory.max/OOM/throttle deltas during paired pressure and held-out queries; pressure max increments indicate mixed or possibly cap-confounded pressure. OOM/throttling always block. The shared host floor is checked before every verification/pressure chunk. Reconcile cadence/duration and the full deadline remain bounded. Continuous accounting covers gaps between passes. Existing file charges are not claimed to have migrated into the clone cgroup.

Required frames are `pressure-complete`, `query-ready`, `query-finished`, `released`, `unpin-complete`. Query completion is provisional until released true, actual child disappearance and controller exit zero. Failed cleanup never validates a case. Fixed errors omit raw paths, arguments, payloads and exceptions. Counter windows include helper/background activity; timestamp fences are not exact single-query attribution.

Only the predeclared native control must demonstrate at least 64 MiB of selected nonresident data pages immediately before the query, positive major faults and Qdrant **serverMs >= 1500**. This compares cold-plus-archive-pressure with pinned-plus-archive-pressure; it does not isolate archive pressure's incremental effect. Before-to-post residency loss remains descriptive. The valid red native baseline and successful pinned pair are required before any held-out comparison or complete result. A wall-only tail is transport/other evidence. Other held-outs can have fast baselines and still provide parity/nonregression coverage. Candidate server and wall time must both be below 1500 ms. Paired raw-range cohorts, actual pins, clean limits and sorted per-ID score parity are required. Ordered ID/score parity is reported separately, including tie-order changes.
