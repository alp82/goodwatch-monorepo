# Local production supervisor preparation

This separate supervisor is unpublished and uninstalled. Default invocation emits one fixed `prepared` event without Docker, source inspection, mapping, pinning or queries. A successful clone pin proves neither this wrapper's production placement nor latency under backup pressure. Production promotion remains blocked on the reviewed clone comparison and separate rollout review.

`production.py` reuses `pin.py` and `runtime.py`; it never imports clone lifecycle/pressure controls. Its parent stays outside Qdrant's cgroup and performs bounded Docker inspection. Only its owned spawned holder joins the inspected source cgroup. The holder validates actual proc identity locally, holds allocated data extents, and releases on error, EOF, a 60-second idle command lease or kernel parent-death SIGTERM. Source-RPC replies remain bounded to fifteen seconds, allowing margin beyond the two bounded five-second Docker inspections. Parent pass deadlines remain 180 seconds initially and 30 seconds thereafter. The idle lease permits the normal ten-second reconcile interval plus bounded parent Docker inspection delays; it does not delay EOF/kernel parent-death shutdown. Its parent owns terminate/kill/reap evidence; forced exit is distinguished from graceful release acknowledgement. Qdrant is never restarted by this module.

A dedicated watchdog reads host MemAvailable without Docker/RPC dependencies. Below the frozen emergency floor, or on unreadable headroom, it terminates only the attached holder, escalating to kill after five seconds. Thus blocked source inspection cannot indefinitely hide pressure from the holder. Normal reconciliation remains every ten seconds with 180-second first/30-second later pass deadlines and 32 source-RPC requests per pass. The two-second watchdog cadence is a target; scheduling/proc-read stalls are not ruled out. Kernel uninterruptible waits cannot be promised to resolve by a user-space deadline; missing actual exit remains failure.

The template intentionally contains null live source and archive-bound fields. It cannot execute. Resolve exact canonical Docker volume source, full mount tuples, current Docker MemorySwap and cgroup limits in a separately authorized read-only preflight. This first wrapper accepts only the already observed uncapped production allocation: Memory/MemorySwap/NanoCpus zero, memory.max/high max, cpu.max max/100000 and memory.oom.group zero. Group OOM killing is refused because the holder must not expose the Qdrant process to group termination. Any differing live preflight is a policy decision; this wrapper does not change allocations to fit.

Freeze raw policy SHA and combined pin/runtime/production source SHA before staging. Policy requires maxlock at most 2 GiB, payload false, reserve at least reviewed archive bound plus 2 GiB, emergency floor at least 1.5 GiB, explicit cap/VMA reserves. There is no production pressure-window counter exception. Existing page charges are not claimed to move between cgroups. All class extents and payload exclusion remain measured. The archive bound must remain valid for the backup workload; checking future archive growth is still a rollout integration requirement.

The runtime directory is fixed `/run/goodwatch-qdrant-pin`, canonical, root-owned and private. Parent and holder use separate exclusive locks there. Installation must create that dedicated directory; no directory is created by default or by policy parsing. The helper has no query/network endpoint. Unknown CLI/error text is discarded; state output retains only fixed enums, numeric evidence and hashes.

Twenty-four module fixtures cover policy/privacy, actual owned subprocess termination, independent emergency escalation, EOF/lease handling, source change during a blocked pass, clean SIGTERM and lifetime expiry, fixed failure reporting, source hash changes at spawn, group OOM rejection and exact file-descriptor budget proofs. A real 16 KiB anonymous locked mapping supplies the parent proof fixture: the parent reads actual VmLck and cgroup placement, rejects mismatched Qdrant identity/lock budgets, reaps the old holder before source turnover and receives graceful release acknowledgement. The fixture uses the test process's cgroup and source interface; it does not prove production foreign-cgroup joining, full mapped-file selection, permission/capability availability or application latency. The scaled lease fixture alone replaces state sanitization to isolate the command timing seam.

The parent freezes its expected helper hash for the entire run and passes it to each spawned holder. Before emitting heartbeat evidence it requires a live holder. Emergency release, whether detected by the parent accounting check or independent watchdog, kills the owned holder immediately before slower cleanup. The watchdog remains attached until cleanup has observed holder exit. Source PID/start ticks, policy maxlock and actual VmLck are cross-checked independently of the holder's claims.

Separate local operational drafts provide a private fsynced numeric journal, offline supplemental seven-day coverage checker, service wrapper, owned unit template and atomic publisher/rollback library. Five operation fixtures exercise real file locks and privacy, exact owned-file publication/rollback and synthetic coverage rejection for missing frames, collector restart, source changes, stale replay and release. Synthetic seven-day coverage is test data. The verifier always reports application acceptance false; actual search lifecycle/history and both ingress collectors are separate required evidence.

The publisher CLI remains prepared-only and refuses execution until the live-holder release/absence gate is integrated and reviewed. Library fixtures operate only in temporary directories. The unit template is uninstalled and has Restart=no; its required capabilities and foreign-cgroup child cleanup have not been proven on production. No journal or service has been launched.

Still required before execution: independent review of the revised module and operational files; integrated live-holder release/absence publisher guard; resolved source/archive-bound policy; zero-pin live placement/permissions gate; actual production holder limit/release proof; and bounded PR446 pressure collection during an authorized backup trial. Do not copy the clone controller's Docker-stop gate into production. Continuous helper journal/source coverage supplements the application collectors. No acceptance window starts with this preparation.

The focused v3 revision also replaces both quadratic descriptor cleanup loops with one shared identity-set pass. Its 20,000-held/20,000-fresh fixture counts exactly 20,000 mapping visits and separately verifies actual unheld FD closure while retained FDs stay open. The installed clone helper is unchanged.

The broad target-identity guard still combines inode/link failures and is never retried. The narrower revision below introduces specific benign-race enums. Conservative steady-state VMA double counting remains a safe rejection limitation; the actual production permission and backup latency gates remain unproven.

The next local revision implements at most two retries for precisely classified mapped-path ENOENT, same-inode/single-link size change and extent churn. Every retry requires zero held mappings, unchanged source and cap, unchanged OOM/max/throttle counters and fresh emergency headroom. The original parent pass deadline is not extended. Each retry emits inventory_retry_claimed evidence, explicitly marked holderClaimed, and therefore invalidates uninterrupted coverage; path/device/link/class/resource guards remain fatal. Real mmap/lock fixture tests check release before re-inventory, the two-retry bound and rejection of memory counter growth and hardlinks. Production foreign-cgroup placement remains unproven by these fixtures.

Owned holder signals now use a pidfd opened before any other thread can reap that direct child, with a lock around signalling/descriptor closure. The watchdog checks kernel pidfd readiness instead of reaping; the parent alone joins/reaps. A real subprocess fixture verifies the descriptor closes and numeric PID-path reuse cannot falsify exit evidence. The child explicitly unblocks SIGTERM after installing its parent-death/default disposition. A scaled real holder fixture verifies bounded source-RPC failure without a parent reply. None of these changes deploys a helper or changes search deadlines, memory limits or the maximum lock policy.

The focused v5 cleanup retains watchdog attachment through source turnover as well as final shutdown. No replacement holder is spawned after a turnover cleanup pressure trip. Released events retain an explicit `emergencyRelease` boolean; a pressure trip at clean loop exit or during normal cleanup produces fixed emergency failure rather than successful exit. Real tests cover pressure during five-second stubborn-holder cleanup and turnover of an actual locked child, checking kernel exit before the graceful close begins. Linear FD cleanup does not imply linear extent-difference arithmetic; highly fragmented extents remain bounded by the existing inventory/pass guards and have not been benchmarked at the declared worst-case extent count.


The v6 parent synchronously emits holder_started with actual PID/start ticks and pidfd ownership before any reconcile command can permit placement or pinning. Production CLI execution now requires the durable journal sink; its acknowledgement becomes true only after the birth append has been fsynced. Every registered child is retained for publisher absence checks, including children that never reached locked state. Missing birth registration is not inferred from a locked record. A real parent-crash fixture registers and fsyncs birth, exits before reconcile, and leaves a deliberately TERM-resistant child to prove publication remains blocked until actual kernel exit/reap. This fixture does not claim that an unregistered pre-command child is observable from its generic multiprocessing argv.

Retry claims are separate from parent-verified lock/release evidence. The parent accepts only ordered attempts one then two and rejects repeats, skips or a third attempt over a real pipe. Claims contain holderClaimed and emergencyRelease, and invalidate coverage. Watchdog-caused pipe disappearance is classified as emergency after the watchdog flag is set. A retained pidfd remains usable when exit is unproven; pressure protection is not disarmed while the holder remains live. Final emergency evidence is captured after true exit and watchdog shutdown. SIGCHLD ignore is refused before spawn so kernel child ownership/reaping is not silently lost.
