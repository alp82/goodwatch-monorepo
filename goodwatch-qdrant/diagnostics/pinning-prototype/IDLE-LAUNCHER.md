# Inactive idle launcher integration

This source preparation enables no CLI execution, stage publication, service, model work, queries or production pinning. The default command prints prepared; `--execute-reviewed` refuses. Only a later reviewed owner/stager may call the prepared `run_reviewed` API after freezing code, private source and scheduler contracts, current-hash zero-placement evidence, and adequate fresh resource/schedule proof. A future production trial remains a separate decision and cannot overlap an unpinned observation window.

`idle_launcher` calls the existing public `idle_trial.run`, with its fixed policy, shared supervisor/holder locks and production timings. It changes no idle/core policy. It verifies the complete nine-module source manifest against canonical root-owned mode-0400 files without aliases or a pycache directory. These checks verify file bytes; they do not independently prove previously imported Python instructions. The future transport must verify the stage before starting a fresh direct-file `python -I -B` interpreter, bind code and private-input hashes, and preserve that root-owned stage. A privileged root writer could still rename or mutate it; source checks are not protection against such a writer. Inline oversized `python -c` transport is unsuitable for the strict process-argument census.

The wrapper verifies source identity/allocation and parent outside-source placement before creating a writer. It then checks exact source PID/start ticks/identity, own VmLck zero, source swap zero, and the existing idle sample's source/ancestor/resource fences in the journaled preflight before any holder. The kernel parent lifetime backstop is 400 seconds. It stays armed when an exception or missing exit proof prevents verified cleanup; the source is never signalled. The wrapper retains a separate PID-fd for every registered actual direct child before durable acknowledgement, excluding source and self PIDs, and observes actual exit before closing that ownership handle. Residual live owned holders receive KILL through those PID-fds. These are owned-holder release measures, not a foreign-process census or proof that no unregistered early child ever existed.

`idle_journal` accepts only fixed enum/hash/numeric/boolean frames, exact nested pressure metrics and actual holder state/release fields. Unknown fields, private error strings, query fields, missing required pressure metrics, altered source hashes and malformed birth proofs refuse. Each record is at most 32 KiB, the journal at most 16 MiB/512 records. A new private journal is created exclusively through a fenced directory FD, never by reopening a previous or torn-tail file.

An owned outside-source writer process writes, fsyncs, and reads back each exact record before returning its hash/sequence receipt. Birth acknowledgement requires that receipt to match the parent's retained child identity and expected record bytes. A uncertain commit never authorizes a placement/reconcile command. Callback RPC waits at most one second in userspace; on timeout it sends owned writer KILL and defers bounded reaping to overall cleanup. Signal syscalls, proc reads and kernel I/O have no absolute userspace interruption guarantee. A failed writer leaves the callback poisoned; the trial's independent pressure guard still protects an already registered holder. Writer PID-fd exit proof and the trial's cleanup proof are retained separately; journal failure cannot become a successful evidence receipt.

`idle_lease` pins the established UTC cron executable/daemon, launch/environment hashes, namespace, timezone metadata, actual root table, backup source, verified `uv run` invocation and latest known phase completion. Its accepted invocation is an absolute `uv`, literal `run`, absolute backup script, then log redirection; it accepts no generic shell or Python wrapper. The next monotonic boundary derives from the freshly verified table minute rather than a minute-15 assumption. Clock jumps, source/table changes, active known backup commands, unknown or vanished process-census entries, incomplete/failed phases and completed reads over one second refuse. The fixed source contract must bind the observed daemon/UTC/command proof; arbitrary caller configuration is not a substitute. Known backup/snapshot checks do not exclude unrelated snapshot clients. The API's stable boundary/hash and fresh lease are then checked by the unchanged idle module.

Local tests include actual owned writer timeout, fsynced birth receipt and wrong-receipt rejection, exclusive journal creation, recursive privacy validation, process-census uncertainty, real filesystem source changes, active known jobs and changed schedule/clock. One complete real public `idle_trial.run` sequence uses its production 30-second baseline and 30-second hold, actual owned mapped files/holder, and explicitly fake source/placement interfaces. Every actual frame passes the strict writer schema; it ends with graceful holder and writer exit zero. This does not prove actual production placement, source-cgroup charging, headroom fit or latency improvement. The independent current-hash zero gate establishes its narrower lifecycle/permissions scope only.

No production idle trial, service activation, search latency acceptance or seven-day completion is claimed. Map #100 remains responsible for the latency remedy; #406 stays closed and #407 retains acceptance work.

## V2 review closures and limits

The new source-contract API accepts a private path and SHA-256, loads the exact existing contract parser, and records both that hash and the nine-file packet hash as the first fsynced journal record. The result retains the final committed record sequence/hash so a missing journal tail is observable. Private contracts and policy/schedule inputs belong outside the clean code directory. That code directory contains exactly the nine manifest-listed modules (including the direct-file launcher); each ancestor must be root-owned and not group/other writable. Tests and review assets are outside the eventual code stage.

After packet/contract and initial source-placement verification, policy and later source/schedule refusals are recorded as terminal refusals; only that frame may have a null schedule hash. Packet/contract/context and first-source failures (Docker/source unavailable, changed allocation or OOM group, and placement refusal) return a fixed unjournaled refusal, explicitly marked `journalCreated: false`. The caller must retain those results. No raw exception or private path leaves the wrapper. Holder release failure cannot skip writer cleanup.

The private schedule configuration now has an exact schema, a nonempty timezone-file list including `/etc/localtime` resolved to canonical UTC, and daemon/self mount-namespace equality. Completed cache advice requires the exact boolean `true`. Shadow backup commands, wrappers, shorthand jobs and relative backup names refuse. The census is only a known-job premise: it proves the pinned single root table and daemon, not other users' tables, `/etc/cron.d`, systemd timers or unrelated snapshot clients. A verified caller must establish that scope from the standing host proof. Process churn and fsync-related PSI can still yield an inconclusive or safety-aborted trial; no pressure fence is relaxed to make a trial pass.

The actual V1 Opus review is preserved unchanged; its missing-cache-advice finding was disclosed at review time. V2 corrects the six concrete source/evidence blockers. Local fake-placement tests do not establish actual root execution, future pin headroom, or latency.

## V3 focused closures

Result reasons use explicit safety/main/first/post-release/cleanup/completion precedence, including null completion fields and late outcome downgrades. A journal startup failure may have already created a partial file; the outer result therefore marks `journalCreationUnknown: true`, retains the lifetime backstop, and never claims that no journal exists. Refusals before entering journal startup remain explicitly unjournaled.

V2 is preserved with its actual Opus review and validation qualification. V3 adds exercised real wrapper preflight/lease/timer/mask behavior and an actual core `_run` refusal through the strict journal, then validates the final frozen bytes with the complete integration suite. No core, policy or timing change is part of this revision.
