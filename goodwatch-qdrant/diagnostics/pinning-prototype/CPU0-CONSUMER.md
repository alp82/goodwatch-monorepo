# Prepared CPU0 consumer and offline contract

These additive modules target only the owned disposable CPU0 clone. The default consumer entry prints `prepared-only`. This local source packet has not been staged or executed on any host and does not prove causal latency, production headroom, a production remedy, or application acceptance.

The actual caller must bind the reviewed fourteen-file owned-lifecycle source freeze, the closed external public manifest, and the existing committed predecessor handoff. The consumer derives its four code/policy identities from the verified source freeze. It rejects the previous twelve-file schema, canonical comparison adapter, CPU2 policy, missing lifecycle source, changed core aggregate, alias drift, and changed reclaim helper. The four immutable CPU0 core files remain unchanged. Node and its copy provenance are separately pinned by the outer transport, outside the public manifest; their presence in the same stage is expected. Public files and policies are mode 0600 in an owned canonical mode-0700 stage; Node is mode 0700. Phase-created instance locks and bounded writer receipts are authenticated by the independent outer, rather than treated as arbitrary new public code.

The consumer invokes the reviewed six-argument preflight with a fixed environment containing only PATH, LANG, LC_ALL and the local Unix Docker socket selector. That entry acquires the shared control lock, checks the supplied predecessor, admits the current source, and commits one owned handoff. Its public `consumer-admission` frame carries the source and external manifest hashes, the complete preflight receipt and the actual consumer birth. Bounded metadata reads fence own and source PID/start ticks, cgroup and executable identities before and after; own VmLck must be zero and its cgroup must lie outside the source subtree. The executable identity uses compact JSON bytes without a newline, matching the lifecycle inspector; persisted handoffs alone include a newline. The pure `validateAdmissionFrame(frame, previous, {sourceFreezeSha256, externalManifestSha256})` export validates the complete frame and returns its receipt and consumer birth. The external pipe must independently confirm and register that reported real birth before releasing producer capture. The external pipe must see and authenticate this frame before it selects or starts the private producer. Preflight therefore performs a public handoff write; it is not globally read-only.

Private packets are bounded in memory and remain unread until entry preflight succeeds. EOF and a successful producer-completion frame must precede every clone query. The external transport separately proves the real producer exit. Nine historical slots allow at most nine pairs and eighteen registered reclaim writers. Ambiguous excluded history slots, lookup-based query payloads, duplicate slots, a missing native anchor, wrong cached-index version, truncated input and data after completion refuse the run.

Each phase passes its exact predecessor handoff to the owned controller. Before querying, the consumer validates the three ready frames, fresh admitted births, actual four-element runtime source identity, completed child-only graceful stop, cache-preparation/writer/quiescence/resource proofs, shape, CPU hierarchy and fixed policies. Initial setup alone permits owner `setup` and a null predecessor. Successor receipts require the previous SHA. The source identity is `(container ID, image, actual Qdrant PID, start ticks)`; cgroup identities are retained separately. Non-root CPU rows contain quota, period and throttle counters. Hierarchy-root rows also contain required usage/user/system counters with typed bandwidth non-applicability. Root counter changes are not added to overlapping descendant counters.

Each direct HTTP batch owns a new socket, sends `Connection: close`, preserves the thirty-second timeout, and closes the socket before the query acknowledgement. Wall time includes teardown. There are no query retries. A phase advances only after the authenticated controller handoff, released and unpin-complete frames and actual observed CLI exit zero. Any failed frame, missing cleanup, changed handoff, connection failure or refused proof terminates the comparison. Failure output preserves validated completed clean-stop receipts, admitted failed-stop births and observed nonclean final states, the fixed backend cause, CPU/host-CPU facts, resource endpoints with checked signed deltas, explicit missing measurements, and cleanup/finalization evidence. Nonzero exit codes and observed OOM flags remain failure evidence; they never promote a clean stop. Raw failed frames and errors are omitted. The static backend cause set is tested against the frozen producer scalar enum without importing or executing its runtime.

The offline auditor imports only pure contracts. It recomputes the phase chain, mandatory native red mechanism, candidate tail threshold, ID/score parity and all nine slots from retained public frames. Both row kinds use the same consumer emit builders; they retain both actual controller exits and explicit socket-closure facts. This closes a V1 review finding where the real paired row omitted its baseline exit while synthetic audit fixtures included it. Result points require supported Qdrant scalar IDs and finite numeric scores before any parity hash; valid empty results remain supported. Its result explicitly keeps `experimentPass: false` and requires the independent external cleanup audit. It cannot establish writer/holder disappearance from a remote SSH exit, and it cannot turn clone results into application acceptance. The external completion ABI remains a separate reviewed dependency.

The public test cohort uses real owned child pipes, actual socket teardown, aborted HTTP responses and the unchanged thirty-second stalled-header timeout. It also evaluates only the actual immutable runtime's source-identity return expression with public scalar inputs; that fixture does not invoke source inspection or Docker. Synthetic numeric phase fixtures are labeled public fixtures and do not claim measured latency.

Actual host execution still requires root's final packet review, independent lifecycle and cleanup proofs, fresh resource admission and the separately reviewed external setup/pipe. No service, production source, archive, model, query history or ordinary search API is modified by preparing this source.

The unchanged consumer post-ack cleanup/reap budgets are 15/5 seconds. Earlier CPU2 timing is context only and does not establish that every CPU0 phase fits this window. A terminal timeout cannot produce PASS, advance the handoff, or resume a pair; the independent outer must retain cleanup uncertainty. The 131072-byte per-controller-frame limit is likewise a caller protocol bound, not an assertion about unobserved future frame sizes. Aggregate public rows are bounded separately by the offline reader.
