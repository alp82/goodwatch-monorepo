# Prepared idle-only lock/release trial

This local preparation introduces `production-idle-lock-release.v1`. It installs no service and enables no CLI execution: default reports prepared; `--execute-reviewed` refuses. A later reviewed launcher must supply the exact private source contract, frozen code/policy hashes, durable fsynced birth registration, and a fresh verified schedule/job lease. No production trial has run.

The fixed policy locks at most 2 GiB of allocated mapped vector, graph, sparse and other data; payload is excluded. Explicit fields hold a 2 GiB floor and an experimental 6 GiB transient/release-lead allowance. Admission requires 10 GiB effective availability, charging the entire ceiling even for a smaller or resident selection. Retention requires 8 GiB. Effective availability uses one meminfo read: `max(0, MemAvailable - Dirty - Writeback)`. WritebackTmp is recorded without subtraction. The 256 MiB setup reserve is cgroup-side only and is not another term in the host admission sum.

`pin.IdlePolicy` is separate from the unchanged archive-based `pin.Policy` invariant. Legacy production loader, service, publisher and schemas remain unchanged. Idle policy requires the explicit effective-accounting adapter; legacy policy rejects that adapter. Changed core files change code hashes; old frozen deployments cannot be relabelled as this revision. Existing tests verify legacy behavior.

The sequence is a 30-second baseline, exactly one initial reconcile bounded to 180 seconds, a 30-second hold beginning after actual VmLck/cgroup/residency verification, then owned release. The holder rejects a second reconcile and never retries inventory races. Source turnover ends the trial. Every available ancestor memory.max/memory.high must be max; finite ancestor limits are refused rather than treated as unlimited. A 230-second kernel timer is armed before locking with the default SIGALRM disposition. Creation occurs on the main thread, preserving kernel parent-death protection. Shared supervisor/holder lock paths exclude legacy execution.

All required meminfo, source memory/event/CPU, memory/IO PSI and reclaim/refault fields are checked before a holder exists. Missing values never become zero. The reader freezes all required metrics before creating a child and retains trigger observations with the phase at read start; initial and cleanup rows are drained under their own phase. The fresh outer lease verifies known backup/snapshot phases idle, verified schedule hash and next boundary. The entire worst-case envelope plus 120 seconds must fit before it. Unknown snapshot clients remain outside this evidence.

The independent guard reads local proc/cgroup metadata on a two-second target cadence, retaining at most 256 fixed numeric/hash rows. It calls no Docker, FUSE, source RPC or journal. Completed reads over one second fail. Python cannot interrupt a blocked kernel read: main detects a poll stamp over four seconds old; guard detects a main stamp over twelve seconds old. A clock deadline independently enforces hold plus the 20-second cleanup bound. The child kernel timer remains a final lifetime backstop. These are detection mechanisms, not an absolute userspace read timer or protection against arbitrary sub-poll bursts.

Safety triggers cover headroom below 8 GiB, Dirty plus Writeback above 1 GiB, source anon growth above 1.5 GiB, kernel growth above 256 MiB, changed source/ancestor allocation or OOM group, limit/throttle events, counter resets, expired schedule, stale liveness and interruption. The baseline precedes holder placement; holder self-charge contributes to growth. Safety release sends KILL only through the owned holder PID-fd and requires actual exit proof. It never signals Qdrant or backups.

Initial faults are measured. Hold-period allocstall, file refault or memory/IO full-PSI growth ends the quiet claim as inconclusive and starts graceful release. The guard stays armed through cleanup; later safety loss can kill the holder. First reason and its guard/main origin, main failure, later safety reason, observer shutdown, drain failure, post-release observation and cleanup failure remain distinct. Any post-release verification loss is a safety abort even after a proven graceful release; it is not proof that the trial caused that loss. Once the owned holder exists, every failure is urgent except scientific quiet-pressure and normal hold completion. Actual holder PID/start ticks, source cgroup placement and VmLck are reverified against the parent-retained birth identity at hold end. Hold completion is not a guard reason and cannot mask a later failure. PASS requires graceful acknowledgement and actual exit code 0; an alarm, TERM, KILL or missing acknowledgement cannot pass. Exit unproven is a failure. Newly resident unlocked pages can remain cached after release, so baseline equality is not required.

Tests use real subprocesses and mappings for parent/holder hold with actual VmLck, independent KILL during a stalled main loop, kernel SIGALRM during RPC wait, second-command rejection and resident-file admission charged at the full budget. Additional tests cover both adapter directions, required metrics, schedule freshness, mutual liveness and truthful reason retention. Regressions exercise a real signal inside the guard mutex, a late source error after hold expiry, a synchronized scientific trip after the final main fence, a non-acknowledged exit, blocked observer shutdown, actual filesystem ancestor refusal and real exclusive supervisor locks. The real idle holder/PinSet/runtime/adapter path uses a small owned four-file fixture and explicit fake source/placement interfaces; it makes no production placement claim. Short test timings are private test seams; public run uses the fixed production timings.
