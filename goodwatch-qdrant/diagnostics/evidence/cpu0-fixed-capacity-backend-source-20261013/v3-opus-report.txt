## Residual issues (non-blocking)

**R1. A signal consumed inside a `SIG_BLOCK` call skips cleanup and leaves TERM/INT blocked.**
- This rests on CPython behaviour as I recall it, not an observed run: `signal.pthread_sigmask` runs pending Python handlers before returning.
- If a second signal lands between the start-mask restore and the cleanup `SIG_BLOCK`, the handler raises inside that call. The kernel mask is already applied, but `cleanup_mask` stays `None`.
- Effect: the endpoint closes and the reap are skipped, and the mask is never restored.
- The emitted facts stay truthful: unknown after a start attempt, so `released` is false.
- The unreaped child exits only on pipe EOF. If the parent's end is still open at interpreter exit, multiprocessing's exit-time join of a non-daemon child could hang, with TERM blocked.
- The first `SIG_BLOCK` before `start` has the same mask-left-blocked property, with no child; that was already true in 990.
- This is much narrower than the 990 U3 window. Suggested fix: run the cleanup body whether or not the block call raised, and restore to a mask captured once up front.

**R2. Unknown without a reason.** If `start` was attempted and `process.pid` is still `None`, the stream reports `released: false` and `pinChildExited: false` with `cleanupReason: null`. This is truthful but unexplained, and no fixture reaches it.

**R3. Start failure plus a pending signal.** The restore-time `controller_interrupted` replaces the `start` error as primary. The start error survives only as `__context__` and is not emitted. Behaviour is unchanged from 990.

**R4. Carried from 990, unchanged.**
- U4: all guard refusals share `overhead_helper_unproven` with no numbers.
- U5: fd 0 inheritance, the temp-directory symlink assumption and the dead `fake_pin_child`.
- The new N1 test adds one more dependence on the temp directory not being behind a symlink.
