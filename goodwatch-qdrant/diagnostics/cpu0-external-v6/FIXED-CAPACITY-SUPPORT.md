# Fixed-capacity byte-boundary support

These local helpers support the separately reviewed running-clone continuation for map #100. They do not implement that continuation, change memory limits, run a benchmark, or establish production acceptance. Existing v1 validators and staging behavior retain their original meaning.

`verify_source_v2` accepts only `search.clone-cpu0-fixed-source-freeze.v2`, variant `cpu0-fixed-capacity.v2`, the closed four-key manifest and the same fourteen source names. `verify_full_v2` accepts only `cpu0-full-public-packet.v7`, the same variant and the closed twenty-four-file manifest, including byte-exact policy aliases and the unchanged reclaim helper. Both authenticate the entire recipe before executable imports. Successor JSON rejects duplicate keys and nonfinite constants. Distinct first/staged loaders authenticate successor bytes before executing them; no runtime dispatcher calls them yet.

`copy_node_v2` creates a new owned copy through the existing bounded copier, independently rehashes the stable target FD, and adds exact integer `targetMtimeNs` and `targetCtimeNs` to `clone-node-copy-receipt.v2`. Later registration must independently compare these timestamps and the device, inode, size, mode and ownership. Nanoseconds crossing into JavaScript must use canonical decimal strings, since they exceed safe integer precision. A failure in this additional verification retains the created copy; it is not cleanup success. The v1 copy receipt stays unchanged.

`stage_absent_once` creates a new public scope without rollback. Partial writes retain the directory and exact creation/completion counts; another call refuses while that scope exists. This is a publication primitive, not permission to restage or delete an attempt. The future adoption operation must restrict its target to the fixed v2 admission directory and authenticate its closure before calling it.

`running_adoption_proofs.observations` authenticates the immutable failed-recovery output and later read-only memory snapshot already published in #507. It returns historical observations with current-birth, current-admission and continuation flags false. Matching historical identity can never substitute for fresh OS attestation, and the predecessor's cleanup UNKNOWN remains unchanged. This helper is not included in either execution closure yet.

Local validation: `python3 -B -m unittest discover -q` from this directory passed 117 tests. New negative fixtures cover whole-recipe authentication before a hostile import, mixed recipes, duplicate JSON keys, partial one-shot staging, same-size binary modification with restored mtime, ctime drift during the target read, byte drift in predecessor evidence, and false cleanup/birth claims. No hosts or production searches are used.

The remaining runtime requires fresh source freezes, current process and resource proofs, the single spent adoption intent, one actual admission sample, independently renewed identities, registration and cleanup integration, source review and merge before execution. These helpers do not satisfy those gates.
