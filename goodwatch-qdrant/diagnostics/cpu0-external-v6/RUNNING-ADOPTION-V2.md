# Fixed-capacity running-clone continuation

This separate protocol is prepared source. Its existence does not authorize a
host run or establish capacity, latency, cleanup or production acceptance.
The consumed v1 recovery is never retried. The diagnostic host keeps its current
size, four CPUs, and the clone's 6 GiB cap with no swap.

`build_packet_v2.py` prepares only public local files. It requires an explicit
reviewed source14 SHA and a separately authenticated six-file consumer manifest
(`cpu0-consumer-source-closure.v2`). It verifies source14, full24, the immutable
reclaim helper, and the two immutable predecessor observations. Those historical
observations can reject drift; they never attest current identity or admission.
Output files are absent-only and retained on publication failure.

The v7 packet binds a closed SSH dependency manifest and a separate local
execution manifest. `local_entry_v2.py` authenticates all local bytes before
imports, using an absent module namespace. The outer packet must match that
authenticated local manifest before constructing RPC. The remote bootstrap
authenticates all seventeen dependency files before dispatch. Legacy v1 paths,
selectors and manifests retain their distinct meaning.

Initial adoption can inspect the two fixed clones; it cannot start, stop,
create, update or remove them. It fences current processes, old receipts,
consumed recovery bytes and existing controls before staging seventeen files.
Staging consumes the new absent scope. It then publishes an identity-only
intent before the sole running-entry memory sample. Successful admission and
fresh identity/recipe/census fences precede the first v2 handoff and success
receipt. Any refusal retains partial facts and prohibits resumption.

Subsequent staging authenticates the full twenty-four-file recipe and the
copied Node executable. Its original copy receipt is reverified, never replaced
with a newly generated authority. Consumer admission binds the independently
authenticated source, helper code, helper policy, controller policy, external
manifest, adoption intent and Node receipt. Preliminary enrolment precedes
admission; independent registration precedes private producer capture.

The private stream remains bounded and unpersisted. Public control frames are
demultiplexed before private packet grammar. Completion requires the reviewed
nine-pair consumer audit and independent registered lifecycle exit evidence.
Cleanup attempts the independent consumer, prior/current writer, control and
clone observations even if another cleanup check refuses. It preserves the
original operation failure and completed receipts if closing a control FD also
fails. Unknown unregistered children are never declared absent.

Local fixtures use temporary files and explicit stand-ins for source placement
and remote registration. Real local interpreter imports and child pipe exits
are useful composition checks, but cannot substitute for physical VM evidence.
Integrated source review, immutable byte checks, tests and merge precede any
root-controlled host operation. Ordinary production searches require their
separate approved probe scope; seven-day production acceptance remains separate.
