# Continuous Glow client

The current client implements contract2 from `@goodwatch/yepwatch-contracts/continuous`. It uses the approved prototype7e60f253 as a visual reference and the API as the authority. The prototype store, seeded titles, fake people, global pointer handlers and review variants are not product dependencies.

## State and transport

`src/core/continuous/useRoom.ts` combines TanStack Query HTTP snapshots with strictly validated shared WebSocket snapshots. Private state has a separate source revision so a delayed HTTP response cannot restore a pick or vote cleared by another actor. Terminal room expiry/access loss fences late responses. Subscription lease expiry alone reconnects. A failed private repair disables writes, performs bounded repair retries and exposes manual recovery; there is no normal polling.

`PersistentCommands` saves the entire sequenced command before HTTP in native SecureStore or browser sessionStorage. An uncertain response retains exactly that command ID/sequence/body across reload. Commands are serial, a definitive conflict is not success, and other controls remain disabled until reconciliation. Immediate own card movement is explicitly pending. Shared matches, counts, checking and Done always require server state. Client focus stays local when inspecting matches or keeping voting. Picks are hidden immediately if the shared match disappears, even before own-state repair arrives.

Fresh admission carries contractVersion2 and preserves optional invite intent. Existing cookie/native membership is checked before readmission. Browser requests include HttpOnly cookies and never place bearer credentials in storage or URLs. Native requests use the secure room credential adapter. API and websocket origins are public configuration only; the app never connects to Crate or Valkey.

## Activity privacy

The client sends only the contract view and semantic reach/handle/release/answer events. It never sends title, candidate, vote, pick, direction or actual pointer coordinates. Session acknowledgements are issued by the authenticated gateway. Per-session view TTL and gesture TTL are separate; closing one device cannot remove another session for that person. Foreground view renewal does not invent gestures. Activity is cleared and suppressed when disconnected, degraded, backgrounded or unauthorized. Hops and generic paths derive only from real unexpired incoming events, with reduced-motion support. Touch/cursor effects render above the poster, generic peer cards behind it. Shared results can permit inference; the room drawer does not promise anonymity.

## UI

`src/features/glow/` contains the reusable presentation seam, poster responder, theme/icons, score, backdrop, match controls, neutral peer visuals, drawers and platform-specific trailers. The screen uses one Yep and one Nope (`watch`/`pass`) with undo. There is no veto, progress bar, fraction, duration promise, completion gate, consent gate or early-match popup. Confirmed matches stay covered in the voting rail until inspection. Inspecting matches exposes posters and aggregate picks; picking a different title replaces the own pick. Unanimous current valid picks produce Done only after server confirmation.

The default screen is shared couch viewing. Country is a suggestion until confirmed and service choices are actual metadata, never assumed subscriptions. Optional drawers retain per-screen remote/mixed viewing, mood, time and media constraints. Ready refreshes authoritative screen state before confirming; changed screen configuration needs a new explicit confirmation. A late joiner chooses a viewing screen without invented votes. Disconnect never removes someone from quorum.

Continuing shows appears only for a linked member with confirmed saved progress support. No manual history editor exists. Authentication uses initial guest admission and preserves the same room actor. Browser member start returns through the server-owned callback using the original room cookie. Native uses S256, persists verifier/room/state securely before opening the auth session, validates the fixed callback and retained state, then exchanges with the existing room credential. API ownership decides account linkage and prefill. A501 or failed exchange never becomes a fake success.

Trailers accept canonical HTTPS YouTube URLs, use the iframe API on web and an inline WebView player on native, and report actual playback/mute/volume before claiming sound. Allowed embeds keep the in-app player and Play with sound action. YouTube embedding refusals101/150 explain that the trailer cannot play inside the app, hide the audio recovery action, and offer Watch on YouTube. Periodic reports retain errors until actual playback succeeds. Native background pauses playback. Native playback and installed callbacks require device validation; JavaScript exports alone do not establish that they work on a device.

## Live-pointer update (2026-10-23)

The earlier generic-path evidence above describes the initial client. The current proposal client opts in to poster-relative live pointer frames, interpolated at the receiver. Horizontal contact stays fixed during pressed choice swipes to keep the answer private; hover and vertical touch motion follow actual input. Release, background, expiry, and disconnect remove the pointer. Other people receive the same answer hop and sparkles regardless of Nope/Yep. Your own avatar uses a hop for Yep and a wobble for Nope. Older APKs receive the previous activity shape without pointer fields.
