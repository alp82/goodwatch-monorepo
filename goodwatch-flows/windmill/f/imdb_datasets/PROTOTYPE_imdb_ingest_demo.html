Daily IMDb dataset ingest: prototype

Throwaway prototype, 2026-09-25. Its source is PROTOTYPE_imdb_dataset_collector.py in the same folder. That script ran the ingest on real IMDb files and injected the real data shown in the lower half of this page.

The question. Every day IMDb publishes two files: ratings for every title and the list of every episode. We want to download them only when they changed, then write only the values that changed into GoodWatch's existing IMDb rating records (show and movie scores), and keep an episode-by-episode grid with season averages. Does that "compare with what we have, write only the difference" rule behave well when IMDb skips a day, when votes trickle in slowly, when a title disappears, when an episode moves to another season, or when TMDB changes a show's IMDb link?

2. Real data: six runs over real IMDb files

These runs used real files: two older ratings files from the Wayback Machine (published 2026-09-23 and 2026-09-24), an older episode file (2026-08-09), and the live files from datasets.imdbws.com. The target was a scratch database seeded with today's production IMDb values, and nothing was written to production.

3. Real episode grids

The rows are IMDb seasons and the columns are episode numbers. A cell shows the IMDb rating. Grey cells are episodes that exist on IMDb but have fewer than 5 votes. Dashed cells are episode numbers that IMDb does not have at all. The right-hand column shows the vote-weighted season average and the season's total votes. With Check against TMDB on, a red dot marks a cell where TMDB has a different episode title at the same season and episode number, so the rating would land on the wrong episode if we joined by number.
